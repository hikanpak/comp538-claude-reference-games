# sys1-harness

Read `CONTEXT.md` first. It holds the claim, the terminology ledger and the
symbol table, and every term in it is binding. One name for one thing, in
prose, in code and in figures.

This is a course project (COMP538), so the `neurips` venue value is only what the
scaffold requires. `paper/` is Halil's: no agent drafts report prose.

## Rules for every session on this project

- Say who does what with concrete names: Sys1, Gemma, Qwen 27B. Define a term
  before using it, and add no new labels. Halil finds coined shorthand unreadable.
- State earlier results with their scope. One benchmark never becomes a forecast
  for our setting, and it never justifies redesigning the plan on its own.
- Only the first table of `plan/choices.tex` is Halil's. Never present anything
  else as his choice.
- Every number comes from a result file carrying its seed, git commit, environment
  and hardware. Report failures and shortfalls plainly, and never fill in a number
  that was not measured. Test games run once, after every choice is frozen on dev.
- Prose in reports follows plain exact terms, with epistemic labels Proven,
  Heuristic, Empirical or Open. Mathematics goes in compiled files, not chat.
- Append what you do to `lib/work-log.md`, as Halil asked: "note down everything you do".
- Compute limits are in `CONTEXT.md`. Log AI work in `lib/llm-use-log.md`, because
  the course requires disclosure with each deliverable.

## Layout

| Path | What goes there |
| --- | --- |
| `CONTEXT.md` | The claim, the terminology ledger, the symbol table, the current state |
| `sink/` | The drop zone. Nothing reads from it. `ingest.py` empties it |
| `lib/literature/` | Sources, positioning, related work, one note per paper read, gitignored PDFs |
| `lab/src/` | Importable code, with `tests/` and `baselines/<name>/` under it |
| `lab/jobs/` | `<topic>.yaml`, `<topic>.py` and `<topic>.sh`, one experiment per stem |
| `lab/results/<topic>/` | Everything the sweep produced, stem matching the job |
| `lab/data/` | Inputs, gitignored |
| `lib/issues/` | Open work, one file per issue, named `<opened>-<assignee>-<headline>.md` |
| `lib/profs/` | Every PI comment verbatim, the rulings, the dismissed findings |
| `lib/reports/` | The report PDFs, named `<date>-<author>-<headline>.pdf`, and nothing else to read |
| `lib/reports/src/` | Each report's labreport source, data, figures, class and config |
| `lib/reports/reflections/` | Section 0, the author's. No agent writes, edits or signs here |
| `lib/claims.yml` | Every claim in the paper and the record behind it |
| `lib/numbers.csv` | Every number in the paper and the record behind it |
| `lib/INDEX.md` | Generated by `index.py`. Never edited by hand |
| `paper/` | The paper. Overleaf sees this directory and nothing else |
| `paper/contracts/` | The author's claim and topic sentences, written before a section is drafted |

`lab/results/<topic>/` always matches the stem in `lab/jobs/<topic>`. A file
whose reader is a person goes in `lib/`, a file whose reader is a job goes in
`lab/`.

## Names

Every issue, comment, ruling, job, result, report, claim and figure is named by
a slug: lowercase, hyphenated, two to six words. A letter-number key is never a
name. Not `A2`, not `C14`, not `H1`. From any slug, `grep -r <slug> lib/` finds
the issue, the comment that raised it, the ruling, the report and the claim.

Citation keys are IACR style. A PDF is `lib/literature/pdfs/<Key>_<ShortTitle>.pdf`
and it is placed with its note in one step by `place-pdf.py`.

## Paper edits

Paper edits are proposed and never applied. An agent reports the numbers and
quotes the proposed wording verbatim, then waits. The author approves the
quoted text, and only then does the edit happen, once.

Approval is of text, never of a summary. The words "proceed", "go on", "ok" and
"yes" do not approve paper text. The approving turn names what it approves.

A section is not drafted before `paper/contracts/<section>.md` holds the
author's claim sentence and the topic sentences, typed by the author.

Before any multi-paragraph edit, commit. After it, build the diff PDF with the
skill's `paper-diff.sh` and review the diff rather than the prose.

## Rules

- Never invent a number or a citation. Both need a record behind them. Every
  measured number lives once, in `lib/numbers.csv`, and reaches the paper as a
  macro in `paper/results.tex`, which is generated and never edited by hand.
- Every claim in the paper names the report or the note behind it, in
  `lib/claims.yml`.
- A PI comment is recorded in `lib/profs/` before it is answered, and the round
  is not open until it is.
- The epistemic label in the four words, proven, heuristic, empirical or open,
  applies to reports and to chat. It does not apply to paper prose.
- All prose follows the writing rules of the `research` skill. Lint with
  `make lint` from `paper/`.
- One session, one worktree. A session writing to `paper/` takes `paper/.lock`.

## Reporting back

Anything written for a person to read goes to
`lib/reports/src/<date>-<author>-<headline>.tex` in the labreport format, made
by `report-new.sh` and built by `report-build.sh`, which writes the PDF to
`lib/reports/` and leaves no build file behind, with `\lrissue` naming the issue it answers and
`\lrclaims` naming the claims it declares. It opens with the verdict and is
checkable in two minutes.

Run `python3 ${CLAUDE_SKILL_DIR:-$HOME/.claude/skills/research}/scripts/index.py`
after writing anything under `lib/`, so `lib/INDEX.md` stays current.
