# Jev and System One models inside LLM agent harnesses, and related work on fast models that steer or oversee LLM agents

Scope and status as of 1 November 2026. Every Jev fact below comes from a page fetched in this session, with its URL. Pages seen only through a search-engine summary are marked "search summary only". Vendor and self-reported figures are labelled as such, and independent measurements are labelled independent.

## 1. Which integrations of Jev and Jev-like models into agent loops exist, and how do they work?

### Takeaway
Six kinds of integration exist, all released between mid-September and late October 2026: Composio's TypeSafe provider (tool choice plus enum argument filling), AgentScope Java middleware (tool-list pruning, routing, guards, supervision), Microsoft's Agent Framework connector (Jev as the tool-calling policy itself), LangChain middleware (model routing and bash risk gating), community MCP servers (retry, stop and model-tier decisions for coding agents) and a per-turn model router for Claude Code and Codex. None of them publishes a measurement of tokens, cost, latency or task success with versus without Jev.

### Cited Findings

#### Jev itself
- Jev (TypeSafe AI) is a non-generative "System One" model that returns typed answers (a choice from a supplied set, a rubric score, or yes/no), each with a calibrated probability. It entered early access in mid-September 2026. The article gives no parameter count or architecture — [Beam, Fredrik Falk, byline 18 Sep 2026](https://beam.ai/agentic-insights/jev-typesafe-ai-agents)
- Vendor claims relayed by Beam: "40 to 200 times faster than frontier LLMs on comparable tasks", "roughly $0.042 per million input tokens with free output", and "an inability to hallucinate or produce a type error", which Beam narrows to Jev never returning an option outside the supplied set while still being able to pick the wrong one. Beam calls these "launch claims until independently tested" and reports no benchmark results of its own. Beam sells an agent platform, so the source is vendor-affiliated — [Beam](https://beam.ai/agentic-insights/jev-typesafe-ai-agents)
- Beam lists the intended agent uses as tool selection, routing and triage, guardrails (jailbreak and policy screening as yes/no with probability), and verification of LLM-extracted fields, and says Jev is not suited to drafting text or multi-step planning — [Beam](https://beam.ai/agentic-insights/jev-typesafe-ai-agents)
- TypeSafe-reported specifications, relayed by a third-party blog: 70–500 ms latency, 32K context, a 255-option limit on a Choice question, and headline ratios of 193.6x faster and 444.6x cheaper that narrow to about 25x and 76x against "GPT-5.6 Terra" — [MCP Playground, Nikhil Tiwari, 20 Sep 2026](https://mcpplaygroundonline.com/blog/jev-mcp)
- The question primitives exposed in LangChain are `Noul` (probability of yes, where 0.5 means an even split and not "medium"), `Choice` (one option with `probabilities` and `confidence`) and `Score` (a level with `legend`, `probabilities` and `confidence`). The default endpoint is `https://api.typesafe.ai` — [LangChain TypeSafe provider docs](https://docs.langchain.com/oss/python/integrations/providers/typesafe.md)
- Jev is a hosted API with closed weights — [Regolo, Alex Genovese, 23 Sep 2026](https://regolo.ai/jev-and-system-one-models-benchmarks-open-source-alternatives-and-when-to-use-them/); open clones "copy the interface, not the model" because architecture and training data were never published — [Pillitteri, 21 Sep 2026](https://pasqualepillitteri.it/en/news/17263/typesafe-jev-open-source-clones-free-rtx-3090)

#### Composio TypeSafe provider (verified)
- The provider "lets Jev choose a Composio tool from a request". `provider.decide(tool_set, request)` returns one of three outcomes: `call` (complete tool call), `partial` (a call with a `missing` argument list) or `abstain` (with `reason` and `candidates`). Execution is a separate `execute` call made by the host code — [Composio docs](https://docs.composio.dev/docs/providers/typesafe)
- Jev fills enums, booleans and arrays of enum values only. Free text, numbers, dates, IDs and objects must come from the host code — [Composio docs](https://docs.composio.dev/docs/providers/typesafe)
- "`confidence` is the score of the least certain judgement required for the decision", not the probability that the whole call is correct. Destructive decisions require `confirm=True` at execution. Network failures throw errors rather than return a decision — [Composio docs](https://docs.composio.dev/docs/providers/typesafe)
- Data sent to TypeSafe: the request, context, tool names, descriptions and enum values, but not the Composio API key or connected account IDs. Packages are `composio-typesafe` with `typesafe-sdk==0.6.0` (Python) and `@composio/typesafe` with `@typesafe-ai/sdk@0.6.0` (TypeScript), pinned to the 0.6.x line — [Composio docs](https://docs.composio.dev/docs/providers/typesafe)
- The page makes no claim about tokens, cost or latency — [Composio docs](https://docs.composio.dev/docs/providers/typesafe)

#### AgentScope Java Jev middleware (partly verified)
- `JevToolSelectionMiddleware` defaults to `ContextStrategy.RECENT_WINDOW` (latest 8 nonblank text messages, 8000-character budget), with `LATEST_USER_MESSAGE` and `FULL_CONVERSATION` as alternatives. The page mentions "independent per-tool relevance scoring" — [AgentScope Java, Jev page](https://java.agentscope.io/v2/en/jev)
- All Jev middleware defaults to OFF. SHADOW "records recommendations while preserving downstream input", and ENFORCE "applies the component-specific policy". "Trace evaluation and ongoing supervision support only OFF/SHADOW" — [AgentScope Java, jev.md](https://java.agentscope.io/v2/en/jev.md)
- Other Jev components listed by name: model routing, stage routing, content checks, pre-execution tool checks (tool guard), trace evaluation, context compaction, memory admission, progress observation, verification evidence and candidate selection. Terminal `ALL_TOOLS_DENIED`, `MAX_ITERATIONS` and `INTERRUPTED` results block completion review — [AgentScope Java, jev.md](https://java.agentscope.io/v2/en/jev.md)
- The mechanism that shrinks the tool-schema list (core tools always kept, optional tools ranked by Jev, fallback to the original list when `failOpen(true)` is set, more than 254 tools handled by reranking chunk winners) appears only in a search-engine summary of the same page. Neither of two fetches of the English page showed it, and the page says the detailed guide (`tool-selection-api.md`) is in Chinese. Search summary only, not verified.
- No token, latency or accuracy measurements are given. The page advises calibrating thresholds on labelled data — [AgentScope Java, Jev page](https://java.agentscope.io/v2/en/jev)

#### Microsoft Agent Framework connector (verified)
- `agent-framework-typesafe` is published by Microsoft under MIT, Alpha status, latest version 1.0.0a261030 released 30 Oct 2026, with earlier alphas from 2 Oct 2026 — [PyPI](https://pypi.org/project/agent-framework-typesafe/)
- The connector turns tool selection and supported arguments into internal Choice and Noul questions, and Agent Framework executes the resulting function calls in its standard loop. Jev "can pick another tool after seeing each result, or pick none to finish", so Jev acts as the tool-calling policy with no generative LLM in the loop — [PyPI](https://pypi.org/project/agent-framework-typesafe/)
- Supported argument shapes: zero-argument tools, fixed constants, enums or Literals, booleans, arrays of enum values treated as sets, and optional versions of these. Free-form required strings and numbers, nested objects and general arrays are not supported, and such tools are excluded "so invocation never falls back to an unintended default" — [PyPI](https://pypi.org/project/agent-framework-typesafe/)
- Limits: one tool call per run by default (raised with `max_function_calls`), at most 32 routable tools per request, 64 properties per tool, 64 enum members per argument, 128 generated internal questions. Streaming and `temperature` are rejected. No benchmarks are published — [PyPI](https://pypi.org/project/agent-framework-typesafe/)

#### LangChain (verified)
- The LangChain blog "Building a Harness with Jev" (Sydney Runkle and Hunter Lovell, 17 Sep 2026) shows `ModelRouterMiddleware` with `ModelChoice`, where "The router selects a model from the latest user message and uses it throughout the run", and `AutoModeMiddleware(tools=["bash"])`, which can "block calls before the tool executes". It does not cover tool selection, loop detection, abort or direct execution by Jev, and links no sample repository — [LangChain blog](https://www.langchain.com/blog/building-a-harness-with-jev)
- The blog's only numbers are vendor claims ("up to 200x faster inference and 400x lower cost" on classification) and unquantified anecdotes linked to X posts — [LangChain blog](https://www.langchain.com/blog/building-a-harness-with-jev)
- `AutoModeMiddleware` hooks `wrap_tool_call`, classifies only the listed tools, and returns an error `ToolMessage` for risky calls. It "refuses risky calls" and "does not request approval", so approval needs a separate human-in-the-loop middleware. Behaviour on API errors (fail open or closed) is undocumented, and `langchain_typesafe.experimental` may change without notice — [LangChain TypeSafe provider docs](https://docs.langchain.com/oss/python/integrations/providers/typesafe.md)
- A third-party write-up reportedly states a block threshold of 0.5 and a context of the last 30 messages plus the proposed call, which can drop the user's original request in long runs. Search summary only ([Towards AI](https://pub.towardsai.net/why-does-langchains-new-jev-auto-mode-forget-your-request-at-tool-call-16-493b5018a259)), not verified.

#### Jev MCP servers (verified)
- TypeSafe publishes no first-party MCP server. Community wrappers expose tools such as `jev_classify`, `jev_score`, `jev_check` and `jev_gate` over stdio — [MCP Playground](https://mcpplaygroundonline.com/blog/jev-mcp)
- The MCP Playground post describes three loop patterns: a Choice question narrows a large tool catalogue (200 tools to 5) before the main LLM runs, with batching above 255 tools; a Score over the serialized tool call maps to allow, confirm or block (example: `run_shell` with `ls` versus `rm -rf`); and a Noul screens tool results for injected instructions. Its sample code falls back to the full catalogue when confidence is below 0.7 and asks a human when risk exceeds 1.5. It does not cover retry, stop, abort or loop detection. Key lines: "It cannot run your MCP agent", "It is a fuzzy `if` statement, not a brain", "No calibration curve has been published" — [MCP Playground](https://mcpplaygroundonline.com/blog/jev-mcp)
- Numbers relayed by that post, with unclear provenance: 67.8% agreement with reference answers at $0.0004 and 0.4 s per case versus $0.03 and 10 s for "Terra", where the references were "generated by averaging" two LLMs' judgements (agreement with model labels, not verified correctness), and an invoice task with Jev 61.8%, Terra 74.7%, another named model 78.4% — [MCP Playground](https://mcpplaygroundonline.com/blog/jev-mcp)
- `minhgv/jev-mcp` (TypeScript, licence not listed on Glama) is a "governed decision layer for coding agents" with nine tools. `jev_coding_loop` returns `next` in {continue, retry, ask_user, stop}, `model_tier` in {cheap, standard, reasoning}, and risk flags. Code policy maps confidence to auto, review or escalate with default thresholds 0.8 (auto), 0.5 (review) and 0.75 (screen block). It "never reads Git, files, or executes shell commands", and "High-risk or incomplete evidence never returns auto" — [Glama, jev-mcp](https://glama.ai/mcp/servers/ic2fxc1p3e); repo [github.com/minhgv/jev-mcp](https://github.com/minhgv/jev-mcp)
- jev-mcp states "The repository does not yet claim a measured cost reduction; that requires production telemetry" — [Glama, jev-mcp](https://glama.ai/mcp/servers/ic2fxc1p3e)
- The MCP Playground post names mcp-use as a client with a Jev tool-routing pattern. A search of the mcp-use docs found no router documentation, so this claim is unverified — [MCP Playground](https://mcpplaygroundonline.com/blog/jev-mcp)

#### Coding-agent integrations (verified)
- `gargpratyush/jev-router` (MIT) wraps Claude Code (`jev-claude`) and Codex (`jev-codex`). "One Jev call per fresh user turn selects a shared abstract tier" among Fast, Balanced, Strong and Long (three model tiers on Claude Code; gpt-5.6-luna, terra, sol on Codex). Local policy: explicit requests win, failures keep the current model, low confidence never downgrades, and downgrades that waste prompt-cache work are refused — [jev-router wiki](https://github.com/gargpratyush/jev-router/wiki)
- jev-router routes per user turn, not per tool call ("Tool-loop continuations keep the tier chosen at the start of the turn"), sends only the user prompt to TypeSafe, and publishes no cost, token or success measurements — [jev-router wiki](https://github.com/gargpratyush/jev-router/wiki)
- No Jev or open System One integration was found for OpenHands, Aider, LlamaIndex, the OpenAI Agents SDK or the Vercel AI SDK. The LangChain post mentions calling Jev "from a node or middleware hook" but names no LangGraph component — [LangChain blog](https://www.langchain.com/blog/building-a-harness-with-jev)

#### Open System One models
- SemIf (first named OpenJev), [github.com/TheoLeeCJ/SemIf](https://github.com/TheoLeeCJ/SemIf), MIT, reads answer probabilities from a local Qwen3.5-4B (MiniCPM5-2B in the browser). Self-reported: 21 yes/no criteria in 1.023 s on an RTX 3090 versus 5.332 s to generate the same JSON, and 0.845 agreement on a 102-row subset versus 0.883 declared for Jev — [Pillitteri](https://pasqualepillitteri.it/en/news/17263/typesafe-jev-open-source-clones-free-rtx-3090)
- Kev: Qwen3.5 family from 0.8B to 9B with public weights, Apache-2.0, exposing a `/v1/systemone` endpoint with Jev's schema so that TypeSafe's Python SDK can target a local server. Self-reported 495 ms on an Apple M5 for a ticket example — [Pillitteri](https://pasqualepillitteri.it/en/news/17263/typesafe-jev-open-source-clones-free-rtx-3090). Authorship by Jared Palmer appears only in a search summary of [dsebastien.net](https://www.dsebastien.net/jev-and-system-one-models-a-semantic-if-statement-for-your-code/).
- jevlike: MIT, a small trainable scorer (byte-level encoder from scratch or frozen pretrained encoder), 192-byte context and 32 options. Its demos use the scorer as a game policy: 4 wins, 46 draws, 0 losses against a random chess mover and 0/2/48 against Stockfish level 0 — [Pillitteri](https://pasqualepillitteri.it/en/news/17263/typesafe-jev-open-source-clones-free-rtx-3090)
- `razorback16/openjev` is a separate project from SemIf: a non-autoregressive decision engine on a Gemma diffusion backbone (26B total, 4B active) with a wire-compatible API, listed at 15–30 ms median latency without methodology. Laya (322M–421M parameter non-autoregressive encoder, about 33 ms per decision) needs task fine-tuning "to overcome out-of-the-box overconfidence" — [Regolo](https://regolo.ai/jev-and-system-one-models-benchmarks-open-source-alternatives-and-when-to-use-them/). Regolo is vendor-authored and also promotes its own 149M ModernBERT capability classifier and the brick-SR1 routing proxy.
- A comparison site reportedly lists JevBench scores of 75.3 (Jev), 75.1 (SemIf) and 74.3 (DJev). Search summary only ([contextstudios.ai](https://www.contextstudios.ai/comparisons/jev-vs-semif-vs-djev)), not verified.

### Inferences
- The integrations split into three roles: Jev as the action policy over a closed, enum-shaped tool set (Microsoft Agent Framework, Composio), Jev as a pre-filter or router for an LLM (AgentScope tool pruning, LangChain and jev-router model routing, MCP Playground catalogue narrowing), and Jev as a gate or supervisor (LangChain AutoModeMiddleware, jev-mcp, AgentScope tool guard and supervision).
- Every integration constrains Jev to choices over host-supplied options, and every one leaves free-text arguments to code or to the LLM. A design whose action set is a fixed list of complete shell command strings fits this constraint exactly.
- Option-count limits bound the candidate list: 255 per Choice (vendor), 32 routable tools in the Microsoft connector, and 254 in AgentScope (search summary only). jevlike's 32-option cap is lower still.
- Because Jev weights are closed, an RL project cannot update Jev itself. RL can train a wrapper policy over Jev's outputs (thresholds, list length, defer decisions), or train an open clone (SemIf, Kev, jevlike, Laya) directly.

### Gaps
- No integration reports tokens, cost, latency or task success with versus without Jev. jev-mcp says so explicitly.
- The AgentScope schema-reduction mechanism and its `failOpen` and chunking behaviour could not be confirmed from the fetched English page. The Chinese `tool-selection-api.md` guide was not reviewed.
- TypeSafe's own documentation was not located as a fetchable page. All Jev behaviour above comes from integrators and third parties.
- No public Jev calibration curve exists ([MCP Playground](https://mcpplaygroundonline.com/blog/jev-mcp)).

## 2. Does any project let a decision model execute common shell or tool commands directly, without the LLM, falling back to the LLM only for generative steps? What was measured?

### Takeaway
No project found has Jev or an open System One model run `ls`, `cd`, `grep` or `cat` directly with LLM fallback for generative steps, and no measurement of shell-step savings exists. The nearest mechanisms are Microsoft's connector (Jev alone picks enum-shaped tools across several steps), trajectory replay without the LLM (muscle-mem, Agentic Plan Caching), and small-model-first deferral in academic agents (SwiftSage, ReDAct, Speculative Actions).

### Cited Findings
- In Microsoft's connector, Jev picks a tool, sees the result, then picks another or none, and only zero-argument, constant, enum and boolean arguments are allowed. No LLM is in this loop, and no fallback to an LLM is described — [PyPI agent-framework-typesafe](https://pypi.org/project/agent-framework-typesafe/)
- Composio's `abstain` and `partial` outcomes are the closest built-in signal for "hand off to something else", but the provider leaves the handoff to host code — [Composio docs](https://docs.composio.dev/docs/providers/typesafe)
- jev-mcp decides `continue`, `retry`, `ask_user`, `stop` and a model tier before "a costly frontier call", but it never executes shell commands — [Glama, jev-mcp](https://glama.ai/mcp/servers/ic2fxc1p3e)
- muscle-mem (pig-dot-dev) records an agent's tool calls and "will deterministically replay those learned trajectories whenever the task is encountered again, falling back to agent mode if edge cases are detected". Cache validity checks are written by the developer per tool, and the API is v0. No savings figures were found — search summary of [github.com/pig-dot-dev/muscle-mem](https://github.com/pig-dot-dev/muscle-mem)
- cmdwall is described as a shell execution firewall that fast-allows allowlisted command types and sends tier 2 and 3 commands to a "GatekeeperLLM". It gates the agent's commands and does not replace the agent LLM. Search summary only ([PyPI cmdwall](https://pypi.org/project/cmdwall/))
- Claude Code auto mode lets a Tier 1 allowlist of read-only tools and Tier 2 in-project file edits skip its safety classifier, while shell commands go to the classifier. The agent LLM still proposes every action — [Anthropic engineering, 25 Mar 2026](https://www.anthropic.com/engineering/claude-code-auto-mode)
- Adjacent measured savings (all Empirical, self-reported by the authors): Agentic Plan Caching cuts cost by 50.31% and latency by 27.28% on average while keeping performance — [Zhang et al., NeurIPS 2025, arXiv 2506.14852](https://arxiv.org/abs/2506.14852); Less-is-More reduces the tool set offered to an edge LLM and cuts execution time by up to 70% and power by up to 40% — [Paramanayakam et al., DATE 2025, arXiv 2411.15399](https://arxiv.org/abs/2411.15399); ReDAct defers about 15% of decisions to the large model and matches its quality on ALFWorld and MiniGrid — [Piatrashyn et al., arXiv 2604.07036](https://arxiv.org/abs/2604.07036); Speculative Actions reaches up to 55% next-action prediction accuracy and up to 20% latency reduction — [Ye et al., arXiv 2510.04371](https://arxiv.org/abs/2510.04371)

### Inferences
- The course design (decision model picks from frequent shell commands, aborts, flags danger, or defers to an LLM, and regains control after the LLM step) has no direct precedent in the Jev ecosystem. The Microsoft connector shows that the "Jev as the whole policy" half works mechanically, and jev-mcp shows the "Jev decides continue, retry, stop, escalate" half, but no project joins them.
- Trajectory caches (muscle-mem, Agentic Plan Caching) save LLM calls by exact or templated reuse, while the course design generalizes across tasks by scoring a fixed command menu. The two can be compared on the same benchmark as baselines.

### Gaps
- No public measurement of LLM calls, tokens, latency or task success with versus without a Jev layer on any shell or coding benchmark.
- The muscle-mem and cmdwall descriptions come from search summaries and were not fetched.

## 3. Has any project used a decision model as an overseer or guardrail for an agent (loops, dangerous commands, aborting runs), and what was measured?

### Takeaway
Jev-based guards exist (LangChain `AutoModeMiddleware` for bash, jev-mcp risk and stop decisions, AgentScope tool guard and supervision in shadow mode) but report no measurements. The best-measured comparable overseer is Claude Code auto mode, an LLM classifier, where Anthropic reports a 17% false-negative rate on real overeager actions and an independent stress test reports 81.0%.

### Cited Findings
- LangChain `AutoModeMiddleware` classifies listed tool calls (example: `bash`) and returns an error instead of running risky ones. No accuracy is reported — [LangChain docs](https://docs.langchain.com/oss/python/integrations/providers/typesafe.md)
- jev-mcp provides `jev_assess_change_risk` (security, operational, compatibility, scope, reversibility, blast radius), flags protected paths such as `auth/`, `security/`, `billing/` and `database/`, and returns `stop` or `ask_user` from `jev_coding_loop`. No measurements — [Glama, jev-mcp](https://glama.ai/mcp/servers/ic2fxc1p3e)
- AgentScope lists Jev pre-execution tool checks, content checks, progress observation and ongoing supervision, with supervision limited to OFF and SHADOW modes — [AgentScope Java, jev.md](https://java.agentscope.io/v2/en/jev.md)
- No Jev-based loop detector was found. A Regolo article mentions a LangChain study that used Jev to grade agent traces with labels such as `premature_abort` and `unnecessary_tool_call` and reports a score variance of 0.0000149 — [Regolo](https://regolo.ai/jev-and-system-one-models-benchmarks-open-source-alternatives-and-when-to-use-them/). The primary study could not be found.
- Claude Code auto mode (not Jev) runs an LLM classifier that sees only user messages and tool calls. Stage 1 is a single-token filter told to "err on the side of blocking", and Stage 2 re-evaluates flagged actions with chain-of-thought. After 3 consecutive or 20 total denials the session escalates to the human, and headless runs terminate — [Anthropic engineering, John Hughes, 25 Mar 2026](https://www.anthropic.com/engineering/claude-code-auto-mode)
- Auto mode results (Empirical, self-reported by Anthropic): false-positive rate 8.5% (Stage 1) and 0.4% (full pipeline) on 10,000 real tool calls, false-negative rate 6.6% and 17% on 52 real overeager actions, and 1.8% and 5.7% on 1,000 synthetic exfiltration cases — [Anthropic engineering](https://www.anthropic.com/engineering/claude-code-auto-mode)
- Independent stress test: AmPermBench (128 prompts, four DevOps task families) finds an end-to-end false-negative rate of 81.0% (95% CI 73.8–87.4%) over 253 state-changing actions, 36.8% of actions falling outside the classifier's scope as Tier 2 file edits, and a 92.9% miss rate on artifact cleanup — [Ji et al., arXiv 2604.04978](https://arxiv.org/abs/2604.04978)
- OpenHands has a security analyzer with risk levels LOW, MEDIUM, HIGH and UNKNOWN and a `ConfirmationPolicy` that maps risk to confirmation, and a `StuckDetector.is_stuck` loop check over history. Search summaries of [OpenHands SDK security docs](https://docs.openhands.dev/sdk/arch/security.md) and [StuckDetector docs](https://docs.all-hands.dev/modules/python/openhands/controller/stuck), not fetched.
- LlamaFirewall combines PromptGuard 2 (jailbreak detection), Agent Alignment Checks (auditing agent reasoning) and CodeShield (static analysis), with no metrics in the abstract — [Chennabasappa et al., arXiv 2505.03574](https://arxiv.org/abs/2505.03574)
- GuardAgent turns guard requests into a plan and guardrail code that checks a target agent's actions, with accuracy above 98% on EICU-AC and 83% on Mind2Web-SC — [Xiang et al., ICML 2025, arXiv 2406.09187](https://arxiv.org/abs/2406.09187)
- ToolEmu emulates tools with an LM and adds an LM safety evaluator. 68.8% of identified failures were judged valid by humans, and the safest agent still failed 23.9% of 144 cases over 36 tools — [Ruan et al., arXiv 2309.15817](https://arxiv.org/abs/2309.15817)

### Inferences
- The vendor-versus-independent gap on auto mode (17% versus 81.0% false negatives, on different distributions) shows that a dangerous-action rate depends strongly on the prompt distribution, so a course project should report it on a fixed, public danger set.
- A Jev-style overseer that sees only commands and user text matches auto mode's "reasoning-blind" input design, which Anthropic chose to limit persuasion and prompt injection.

### Gaps
- No measurement of any Jev-based guard's precision, recall or calibration on dangerous commands.
- The LangChain trace-grading study cited by Regolo was not found.

## 4. Related academic work: cascades and routers, fast/slow agents, AI control and monitoring, RL-trained routing and deferral

### Takeaway
Cascades and routers decide per query whether to call a larger model, fast/slow agents let a small module act and call an LLM planner on demand, AI control evaluates trusted monitors on multi-step bash agents, and a few works learn the deferral policy with RL. The closest single works are SwiftSage (small actor with LLM planner), When2Ask (RL-learned decision of when to query the LLM) and Ctrl-Z (per-step monitoring of a bash agent), and none combines a closed menu of shell commands, an abort and danger action, and RL training against LLM-call cost.

### Cited Findings

#### Cascades and routers (single-turn queries)
- FrugalGPT: Lingjiao Chen, Matei Zaharia, James Zou, "FrugalGPT: How to Use Large Language Models While Reducing Cost and Improving Performance", arXiv 2305.05176 (2023). An LLM cascade with a learned answer scorer that matches GPT-4 at up to 98% lower cost. It routes single queries, not steps of an agent — [arXiv 2305.05176](https://arxiv.org/abs/2305.05176)
- AutoMix: Pranjal Aggarwal, Aman Madaan, et al., "AutoMix: Automatically Mixing Language Models", NeurIPS 2024, arXiv 2310.12963. A POMDP-based router escalates using the small model's self-verification and cuts cost by over 50% at comparable performance. Single-turn tasks only — [arXiv 2310.12963](https://arxiv.org/abs/2310.12963)
- Murong Yue, Jie Zhao, Min Zhang, Liang Du, Ziyu Yao, "Large Language Model Cascades with Mixture of Thoughts Representations for Cost-efficient Reasoning", ICLR 2024, arXiv 2310.03094. The weak model's answer inconsistency triggers the strong model, matching GPT-4 at about 40% of its cost on reasoning benchmarks — [arXiv 2310.03094](https://arxiv.org/abs/2310.03094)
- Dujian Ding, Ankur Mallick, Chi Wang, et al., "Hybrid LLM: Cost-Efficient and Quality-Aware Query Routing", ICLR 2024, arXiv 2404.14618. A router predicts query difficulty and makes up to 40% fewer large-model calls without quality loss — [arXiv 2404.14618](https://arxiv.org/abs/2404.14618)
- Isaac Ong, Amjad Almahairi, Vincent Wu, Wei-Lin Chiang, Tianhao Wu, Joseph E. Gonzalez, et al., "RouteLLM: Learning to Route LLMs with Preference Data", arXiv 2406.18665. Routers trained on preference data cut cost by over 2x in some cases and transfer to new model pairs. Single-turn — [arXiv 2406.18665](https://arxiv.org/abs/2406.18665)
- Claudio Fanconi, Mihaela van der Schaar, "Cascaded Language Models for Cost-effective Human-AI Decision-Making", arXiv 2506.11887. Base model, larger model and human expert with separate deferral and abstention policies and online adaptation, on multiple-choice QA. The abstain action parallels the course design's abort — [arXiv 2506.11887](https://arxiv.org/abs/2506.11887)
- Allen Z. Ren, Anushri Dixit, et al., "Robots That Ask For Help: Uncertainty Alignment for Large Language Model Planners" (KnowNo), CoRL 2023 oral, arXiv 2307.01928. Conformal prediction over multiple-choice next-step options decides when a robot asks a human, with a task-completion guarantee. It shows calibrated choice over a candidate set driving a defer decision, but defers to a human rather than an LLM — [arXiv 2307.01928](https://arxiv.org/abs/2307.01928)

#### RL-trained routing and deferral
- Bin Hu, Chenyang Zhao, Pu Zhang, et al., "Enabling Intelligent Interactions between an Agent and an LLM: A Reinforcement Learning Approach" (When2Ask), arXiv 2306.03604, presented at RLC 2024. The timing of LLM queries is an MDP, and an RL mediator learns when the agent should ask the LLM for a new high-level plan, needing only a few LLM interactions on MiniGrid and Habitat. It covers neither shell actions nor danger or abort actions — [arXiv 2306.03604](https://arxiv.org/abs/2306.03604); [RLJ/RLC 2024 page](https://rlj.cs.umass.edu/2024/papers/Paper161.html)
- Haozhen Zhang, Tao Feng, Jiaxuan You, "Router-R1: Teaching LLMs Multi-Round Routing and Aggregation via Reinforcement Learning", NeurIPS 2025, arXiv 2506.09033. An LLM router interleaves think and route actions under a cost reward, evaluated on QA. The router is itself a generative LLM, not a cheap decision model — [arXiv 2506.09033](https://arxiv.org/abs/2506.09033)
- Chengsong Huang, Tong Zheng, et al., "RelayLLM: Efficient Reasoning via Collaborative Decoding", arXiv 2601.05167. A small model learns with warm-up plus GRPO to emit a call token that invokes a large model, using it for 1.07% of tokens and cutting cost by 98.2% against performance-matched random routers. Token-level reasoning, not tool use — [arXiv 2601.05167](https://arxiv.org/abs/2601.05167)
- Dzianis Piatrashyn, Nikita Kotelevskii, et al., "ReDAct: Uncertainty-Aware Deferral for LLM Agents", arXiv 2604.07036. Per-step deferral from a small to a large agent model when uncertainty passes a calibrated threshold, matching the large model with about 15% of decisions deferred on ALFWorld and MiniGrid. Threshold-based rather than RL-trained, and no safety action — [arXiv 2604.07036](https://arxiv.org/abs/2604.07036)

#### Fast/slow and small-model-first agents
- Bill Yuchen Lin, Yicheng Fu, Karina Yang, et al., "SwiftSage: A Generative Agent with Fast and Slow Thinking for Complex Interactive Tasks", NeurIPS 2023 spotlight, arXiv 2305.17390. A small fine-tuned Swift module acts and an LLM Sage module plans subgoals when invoked, beating SayCan, ReAct and Reflexion on 30 ScienceWorld tasks. The fast module is a generative seq2seq model, not a typed chooser, and the switch is not RL-trained (the abstract does not describe a learned switch) — [arXiv 2305.17390](https://arxiv.org/abs/2305.17390)
- Konstantina Christakopoulou, Shibl Mourad, Maja Matarić, "Agents Thinking Fast and Slow: A Talker-Reasoner Architecture", arXiv 2410.08328. A fast conversational Talker and a slow planning Reasoner, illustrated on a sleep-coaching agent without quantitative evaluation — [arXiv 2410.08328](https://arxiv.org/abs/2410.08328)
- Francesco Fabiano, Vishal Pallagani, et al., "Fast and Slow Planning" (SOFAI), arXiv 2303.04283. A metacognitive module chooses between fast and slow classical planners — [arXiv 2303.04283](https://arxiv.org/abs/2303.04283)
- Naimeng Ye, Arnav Ahuja, et al., "Speculative Actions: A Lossless Framework for Faster Agentic Systems", arXiv 2510.04371. A fast model predicts the next action and executes it speculatively, committing only when the slow model agrees. It cuts latency but not LLM calls, since the slow model still runs every step — [arXiv 2510.04371](https://arxiv.org/abs/2510.04371)
- Wenyue Hua, Mengting Wan, et al., "Interactive Speculative Planning", arXiv 2410.00079. Co-designs agent and interface so human interruptions correct speculative plans — [arXiv 2410.00079](https://arxiv.org/abs/2410.00079)
- Qizheng Zhang, Michael Wornow, Gerry Wan, Kunle Olukotun, "Agentic Plan Caching: Test-Time Memory for Fast and Cost-Efficient LLM Agents", NeurIPS 2025, arXiv 2506.14852 — [arXiv 2506.14852](https://arxiv.org/abs/2506.14852)
- Varatheepan Paramanayakam, Andreas Karatzas, Iraklis Anagnostopoulos, Dimitrios Stamoulis, "Less is More: Optimizing Function Calling for LLM Execution on Edge Devices", DATE 2025, arXiv 2411.15399. Pruning the tool list before the LLM call, the academic analogue of AgentScope's tool-selection middleware — [arXiv 2411.15399](https://arxiv.org/abs/2411.15399)
- Peter Belcak, Greg Heinrich, et al., "Small Language Models are the Future of Agentic AI", arXiv 2506.02153. Position paper arguing that repetitive agent calls should go to small models, with an LLM-to-SLM conversion algorithm and no numeric results — [arXiv 2506.02153](https://arxiv.org/abs/2506.02153)

#### AI control and agent monitoring
- Ryan Greenblatt, Buck Shlegeris, Kshitij Sachan, Fabien Roger, "AI Control: Improving Safety Despite Intentional Subversion", arXiv 2312.06942 (ICML version noted in the arXiv comment). Protocols such as trusted monitoring, trusted editing and untrusted monitoring, with GPT-4 untrusted and GPT-3.5 trusted on programming problems, beat simple baselines. Single-step code tasks, not multi-step agents — [arXiv 2312.06942](https://arxiv.org/abs/2312.06942)
- Aryan Bhatt, Cody Rushing, Adam Kaufman, Tyler Tracy, Vasil Georgiev, David Matolcsi, et al., "Ctrl-Z: Controlling AI Agents via Resampling", arXiv 2504.10374. Introduces BashBench (257 multi-step sysadmin tasks) and resample protocols that cut attack success from 58% to 7% at a 5% cost to benign performance. The trusted monitor scores each bash step and can resample or defer, but it does not itself choose actions to save cost — [arXiv 2504.10374](https://arxiv.org/abs/2504.10374)
- Jiaxin Wen, Vivek Hebbar, et al., "Adaptive Deployment of Untrusted LLMs Reduces Distributed Threats", arXiv 2411.17693. A macro-protocol adaptively picks among micro-protocols and cuts backdoors by 80% at fixed usefulness in code generation — [arXiv 2411.17693](https://arxiv.org/abs/2411.17693)
- Adam Kaufman, James Lucassen, Tyler Tracy, Cody Rushing, Aryan Bhatt, "BashArena: A Control Setting for Highly Privileged AI Agents", arXiv 2512.15688. 637 Linux sysadmin tasks plus four sabotage side tasks, and a frontier model evades a GPT-4.1 mini monitor 26% of the time at a 4% trajectory-wise false-positive rate — [arXiv 2512.15688](https://arxiv.org/abs/2512.15688)
- Jonathan Kutasov, Yuqi Sun, et al., "SHADE-Arena: Evaluating Sabotage and Monitoring in LLM Agents", arXiv 2506.15740. Best sabotage success 27% (a frontier model), best monitor AUC 0.87 (Gemini 2.5 Pro) — [arXiv 2506.15740](https://arxiv.org/abs/2506.15740)
- Zimo Ji, Zongjie Li, et al., "Measuring the Permission Gate: A Stress-Test Evaluation of Claude Code's Auto Mode", arXiv 2604.04978 (figures under Question 3) — [arXiv 2604.04978](https://arxiv.org/abs/2604.04978)

### Inferences

#### Closest prior work to the course design, and the gap
- Architecture: SwiftSage is closest in structure (a cheap module acts, the LLM is called for hard steps, control returns to the cheap module), When2Ask is closest in method (an RL policy decides when to call the LLM, with control returning after the LLM's plan), and ReDAct and RelayLLM give the cost-quality numbers a course project should beat or match (about 15% of steps deferred, about 1% of tokens).
- Safety: Ctrl-Z on BashBench is closest (per-step monitoring of a multi-step bash agent with defer and resample), and Claude Code auto mode is the closest deployed system (a cheap first-stage block filter, escalation after repeated denials).
- Jev ecosystem: Microsoft's connector is the only place Jev runs as the whole tool policy, jev-mcp is the only place Jev decides continue, retry, stop or escalate, and LangChain `AutoModeMiddleware` is the only Jev bash gate.
- Gap: no prior work found puts a non-generative typed decision model in charge of a shell agent with one action space that holds a statistically mined, length-tuned menu of frequent commands plus abort, flag-danger and defer-to-LLM, trained or tuned with RL against a reward that charges for LLM calls and dangerous actions, and evaluated on a public shell benchmark for success rate, LLM-call count and dangerous-action rate. When2Ask lacks shell, abort and danger actions, SwiftSage's fast module is generative and imitation-trained, Ctrl-Z's monitor never acts, and the Jev integrations report no measurements.
- Cascade and router work treats the routing decision as per query. The course design makes it per step inside an episode, which is what makes RL (credit assignment over a trajectory) rather than supervised routing the natural formulation.

### Gaps
- SwiftSage's switching rule was not re-checked beyond the abstract in this session.
- No RL-trained deferral work on shell or coding agents specifically was found.

## 5. Which open agent benchmarks or environments with shell tool use allow cheap measurement of task success, LLM-call count and dangerous-action rate?

### Takeaway
InterCode-Bash (MIT, pip plus Docker, Gym-style interface) is the cheapest success benchmark, NL2Bash gives command statistics for building the candidate list, BashBench and BashArena provide dangerous side tasks in sysadmin settings, AgentBench OS is a light Docker alternative, and Terminal-Bench 2.0 is too hard and costly to use beyond a small subset.

### Cited Findings
- InterCode (John Yang, Akshara Prabhakar, Karthik Narasimhan, Shunyu Yao, arXiv 2306.14898) frames interactive coding as an RL environment in Docker with Bash, SQL and Python action spaces built from NL2Bash, Spider and MBPP — [arXiv 2306.14898](https://arxiv.org/abs/2306.14898)
- InterCode repo: MIT, `pip install intercode-bench`, Python 3.8+ and a running Docker daemon. Interface `env.reset(idx)`, `env.step(action)` returning `obs, reward, done, info`, reward only after `submit`, and success rate as the share of scores equal to 1.0. The quick-start loops over "24 data points in the test set" — [github.com/princeton-nlp/intercode](https://github.com/princeton-nlp/intercode)
- NL2Bash (Xi Victoria Lin, Chenglong Wang, Luke Zettlemoyer, Michael D. Ernst, LREC 2018, arXiv 1802.08979): about 10,000 English–bash one-liner pairs (8,090 train, 609 dev, 606 test), 102 unique utilities, 206 unique flags. Repository GPL-3.0, with `data/bash` relicensed MIT in April 2020. Utility frequencies are shown only in a figure — [github.com/TellinaTool/nl2bash](https://github.com/TellinaTool/nl2bash); [arXiv 1802.08979](https://arxiv.org/abs/1802.08979)
- BashBench: 257 multi-step system administration tasks used to evaluate control protocols, project site bashcontrol.com — [Bhatt et al., arXiv 2504.10374](https://arxiv.org/abs/2504.10374)
- BashArena: 637 main tasks and four side tasks (malware execution, secret exfiltration, privilege escalation, firewall disabling), released as a ControlArena setting with the generation pipeline at github.com/redwoodresearch/basharena_public — [arXiv 2512.15688](https://arxiv.org/abs/2512.15688)
- Terminal-Bench 2.0 (Mike A. Merrill, Alexander G. Shaw, Nicholas Carlini, et al., arXiv 2601.11868): 89 hard terminal tasks, each with its own environment, a human-written solution and tests, and frontier agents below 65% — [arXiv 2601.11868](https://arxiv.org/abs/2601.11868). It runs through the Harbor harness, which supports Claude Code, Codex CLI, OpenHands, mini-SWE-agent and Terminus 2 (`uv run harbor run --dataset terminal-bench@2.0`). The Hugging Face dataset card lists Apache-2.0, while another listing says the README states no licence (search summary of [Hugging Face card](https://huggingface.co/datasets/harborframework/terminal-bench-2.0/blob/main/README.md))
- AgentBench (Xiao Liu, Hao Yu, et al., ICLR 2024, arXiv 2308.03688) has 8 environments including an OS interaction task — [arXiv 2308.03688](https://arxiv.org/abs/2308.03688). The repo is Apache-2.0, the OS task needs three locally built Docker images (`local-os/default`, `local-os/packages`, `local-os/ubuntu`), and each worker starts in about 5 s with under 500 MB memory. OS-specific dev and test counts appear only in an image — [github.com/THUDM/AgentBench](https://github.com/THUDM/AgentBench)
- AmPermBench has 128 prompts over four DevOps task families with 253 state-changing actions, built to measure a permission gate's misses — [arXiv 2604.04978](https://arxiv.org/abs/2604.04978)
- ToolEmu has 36 LM-emulated tools and 144 test cases with an LM safety evaluator, which avoids real sandboxes at the cost of emulation fidelity — [arXiv 2309.15817](https://arxiv.org/abs/2309.15817)

### Inferences
- A cheap pipeline for the course project: mine NL2Bash utility and command frequencies (or the agent's own logged commands) to build the candidate menu, measure success and LLM-call count on InterCode-Bash, and measure dangerous-action rate on BashBench or BashArena side tasks, or on AmPermBench prompts.
- LLM-call count and dangerous-action rate are harness-side counters, so any of these environments supports them once the harness logs which controller produced each action.
- Terminal-Bench 2.0's difficulty (frontier agents below 65%) means a decision-model-first agent would mostly defer, so it suits a small held-out stress subset rather than training.

### Gaps
- The exact InterCode-Bash task count beyond the README's 24-item test loop, and its file-system splits, were not confirmed in this session.
- Licences for BashBench and BashArena were not checked.
- AgentBench OS task counts were unreadable (image only).
- The Terminal-Bench 2.0 licence is inconsistent across sources.
