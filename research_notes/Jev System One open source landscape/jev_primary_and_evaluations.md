# TypeSafe AI's Jev ("System One" model): primary materials and independent evaluations

Compiled 1 November 2026. Every finding below comes from a page fetched in this session. Vendor claims are marked "(vendor claim)". Pages that failed to load are listed under Gaps. The acronym RLCD here always means TypeSafe's "Reinforcement Learning for Calibrated Decisions". It is unrelated to Reinforcement Learning from Contrastive Distillation (arXiv 2307.12950), which appears nowhere in TypeSafe's material.

## 1. What Jev outputs, the API, where it is served, and its price, latency and limits

### Takeaway
Jev takes a text or JSON `state` and a map of typed questions, and returns one typed answer per question with a probability distribution. There are three text primitives (Choice over up to 255 user-supplied options, Score on a rubric of up to 10 levels, and Noul for a true/false probability) and an image-only Box primitive. It is served at `POST https://api.typesafe.ai/v1/systemone` and through Vercel AI Gateway. It costs $0.042 per million input tokens with output free, allows 32k tokens per question and 64k per request, and an independent study measured a mean client-side latency of 0.36 s.

### Cited Findings

**Primitives and answer shapes (vendor documentation)**
- TypeSafe defines a System One model as one that evaluates a state and returns typed answers and probabilities. It does not write replies, produce code or explain its reasoning — [TypeSafe docs, System One](https://docs.typesafe.ai/concepts/system-one)
- The documented text primitives are Choice (pick one of a defined set), Score (rate on a defined scale) and Noul (true/false probability). The concept page lists no "extraction" or "branching" primitive. It says users ask independent questions and combine the answers in deterministic code — [TypeSafe docs, System One](https://docs.typesafe.ai/concepts/system-one)
- The API reference lists four question types: `noul` (optional `criteria` with `true`/`false` keys), `choice` (required `criteria` mapping option names to descriptions, with descriptions allowed to be null, **1 to 255 options**), `score` (required `criteria` array of level descriptions, position sets the score from 0, **1 to 10 levels**) and `box` (locates what `instructions` describe in an image, requires the header `TypeSafe-Danger-Zone-Images: true`) — [TypeSafe API reference, System One](https://docs.typesafe.ai/api/system-one.md)
- Answer fields by type: Noul returns `noul` in [0, 1] and no confidence. Choice returns `choice` (the highest-probability option), `confidence` in [0, 1] and `probabilities` per option (summing to about 1). Score returns `score` (the probability-weighted expected level, which can be fractional), `confidence`, `legend` and `probabilities`. Box returns `box` coordinates as fractions of image size and a `confidence` that may be null — [TypeSafe API reference](https://docs.typesafe.ai/api/system-one.md)
- The Choice page says the model never sees the question ID, which serves only to key the answer. It defines Choice as selecting one option and documents no multi-select mode — [TypeSafe docs, Choice](https://docs.typesafe.ai/primitives/choice)
- Confidence for Choice is the normalized top probability, that is the top probability minus 1/n, divided by 1 minus 1/n, for n options. Only the top probability enters, so (0.6, 0.3, 0.1) and (0.6, 0.2, 0.2) both give 0.4. Score confidence penalizes mass on distant levels more than on neighbouring ones. Noul returns no confidence, and the page suggests the absolute value of 2p minus 1 as an equivalent. The page does not claim that the confidence statistic is itself calibrated and calls it one reasonable summary among several — [TypeSafe docs, Confidence](https://docs.typesafe.ai/confidence.md)
- The documentation index also lists cookbooks for date extraction, pre-parsed value extraction, re-ranking and line-by-line search, all built from the primitives above rather than from separate primitives — [TypeSafe docs index (llms.txt)](https://docs.typesafe.ai/llms.txt)

**Request and response**
- Base URL `https://api.typesafe.ai`, endpoint `POST /v1/systemone`, authentication with `Authorization: Bearer <API_KEY>`. The body has required `model`, `state` (string, object or array) and `questions` (at least 1, no stated maximum), plus optional image `assets`. The response has `model` (the versioned model that answered, which can differ from the alias sent), `answers` keyed by question name, and `usage.input_tokens` / `usage.output_tokens` — [TypeSafe API reference](https://docs.typesafe.ai/api/system-one.md)
- `GET /v1/models` lists the aliases. Versioned IDs are accepted whether or not they appear in the list — [TypeSafe docs, Models](https://docs.typesafe.ai/models)
- A worked request through Vercel AI Gateway sends a Noul question on "I was charged twice for my subscription." and receives `{"type": "noul", "noul": 0.98}`, with `usage` of 275 input tokens and a gateway cost of $0.00001155 — [Vercel docs, TypeSafe API with AI Gateway](https://vercel.com/docs/ai-gateway/sdks-and-apis/typesafe.md)
- Request rules: body at most 32 MiB (413 above), UTF-8 JSON, at most 64 levels of nesting in `state`, `instructions` and `criteria`, finite numbers only, optional gzip or zstd compression. Error codes are 400 (including `max_tokens_exceeded`), 401, 413, 415, 422, 429 (rate limit) and 529 (overloaded). The SDKs retry 429 and 529 with exponential backoff — [TypeSafe docs, Request rules and errors](https://docs.typesafe.ai/api/errors.md)
- Official SDKs exist for Python and JavaScript/TypeScript (`@typesafe-ai/sdk`, `TypeSafeClient.systemOne(...)`) — [TypeSafe docs index](https://docs.typesafe.ai/llms.txt); [Vercel docs](https://vercel.com/docs/ai-gateway/sdks-and-apis/typesafe.md)

**Model IDs**
- `jev-1.14.0` is the newest release, available from 14 October 2026. `jev-1.13.0` is the previous version. `jev-latest` and `jev-preview` both point to `jev-1.14.0`. `jev-latest` is the SDK default. Aliases move when a release ships, so answers can change without code changes, and TypeSafe advises sending a versioned ID when confidence thresholds were tuned for that version — [TypeSafe docs, Models](https://docs.typesafe.ai/models)
- The independent benchmark paper pinned `jev-1.13.0` and noted that `jev-latest` would move — [arXiv 2609.37647 (HTML)](https://arxiv.org/html/2609.37647)
- TypeSafe's function-calling cookbook still uses `jev-1.12` — [TypeSafe cookbook, Function calling](https://docs.typesafe.ai/cookbooks/function_calling.md)

**Price, context, rate limits, inputs**
- Jev 1.14 and 1.13 cost $42 per billion input tokens ($0.042 per million). Output tokens are free (vendor claim on pricing, but it is the published price) — [TypeSafe docs, Models](https://docs.typesafe.ai/models); same figure in [TypeSafe launch blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- Context: 64k tokens per request (state plus all questions) and 32k per question (state plus any one question), with no limit on question count as long as both limits hold. The header `TypeSafe-Danger-Zone-Long-Context: true` raises both limits to 262k tokens at the same per-token price, and TypeSafe says the long-context mode is slower and less accurate — [TypeSafe docs, Models](https://docs.typesafe.ai/models)
- Rate limits are set per organization in tokens per second and requests per second and are shown in the developer console. No numeric defaults are published. Higher limits come with custom and enterprise plans — [TypeSafe docs, Models](https://docs.typesafe.ai/models)
- The benchmark authors ran up to 1,100 requests per minute with 32 concurrent connections from one machine and report that throughput was bounded by the rate limit rather than by the service — [arXiv 2609.37647 (HTML)](https://arxiv.org/html/2609.37647)
- Input: the models page says text only, with no audio or video. English is the primary training language and gives the best accuracy. CJK and other languages are handled less well — [TypeSafe docs, Models](https://docs.typesafe.ai/models). The API reference nonetheless documents PNG/JPEG image assets behind the `TypeSafe-Danger-Zone-Images` header for the `box` primitive — [TypeSafe API reference](https://docs.typesafe.ai/api/system-one.md)
- The Choice page states that adding questions to one request barely changes response time because the questions are evaluated in parallel, though each question costs tokens. It does not describe latency as a function of option count (vendor claim) — [TypeSafe docs, Choice](https://docs.typesafe.ai/primitives/choice)
- Above 255 options, the launch blog describes a two-stage process of independent scoring followed by an explicit choice, which can slow responses (vendor claim) — [TypeSafe launch blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)

**Latency**
- Vendor: end-to-end response time of 70 ms to 500 ms, measured from laptops on the US West Coast, against 3 s to 329 s for frontier LLMs (vendor claim) — [TypeSafe launch blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- Vendor: the launch press release, as summarized by Dealroom, claims latency under 100 ms (vendor claim) — [Dealroom news](https://dealroom.co/news/151032-typesafe-exits-stealth-with-40m-seed-to-build-ai-for-software-n)
- Independent: mean client-side latency of 0.36 s per request at 32 concurrent requests, with category means from 0.35 s to 0.37 s, network time included — [arXiv 2609.37647 (HTML)](https://arxiv.org/html/2609.37647)

**Where it is served**
- TypeSafe's own API, in early access, with developers admitted from a waitlist through the TypeSafe console — [TypeSafe launch blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- Vercel AI Gateway: TypeSafe-compatible base URL `https://ai-gateway.vercel.sh/typesafe`, model ID `typesafe-ai/jev`, endpoints `POST /typesafe/v1/systemone` and `GET /typesafe/v1/models`, billing through the gateway or BYOK. The gateway adds "decision fallbacks", which rerun a successful but uncertain decision on another model, for example `openai/gpt-6-astra` when the confidence of a named question falls below 0.6. When a language model answers a Choice or Score question in fallback, it returns `confidence: 0` and `probabilities: {}` as a sentinel meaning "unavailable" — [Vercel docs, TypeSafe API with AI Gateway](https://vercel.com/docs/ai-gateway/sdks-and-apis/typesafe.md)
- OpenRouter: the URL `https://openrouter.ai/typesafe/jev` returned HTTP 404 when fetched, so no OpenRouter listing is confirmed (see Gaps).
- Third-party integrations: AgentScope Java ships a Jev extension with a `JevToolSelectionMiddleware` — [AgentScope Java docs, Jev](https://java.agentscope.io/v2/en/jev.md)

**Customization**
- Jev is not fine-tuned or adapted per account. All accounts share the same weights, which are trained with RLCD. Jev is not trained on customer requests or responses — [TypeSafe docs, Models](https://docs.typesafe.ai/models)

### Inferences
- The Vercel example is internally consistent with the list price, since 275 input tokens at $0.042 per million is $0.00001155, which suggests the gateway resells at list price with no surcharge.
- The 0.36 s independent mean sits inside the vendor's 70 to 500 ms range but well above the press release's "under 100 ms". The difference likely reflects network distance (the authors are in Germany) and concurrency, which the paper does not separate.
- [Design] An action list of roughly ten shell commands plus abort, flag-danger and fall-back-to-LLM is far below the 255-option ceiling, so the option limit binds only if commands are enumerated together with their arguments (for example one option per `cd <dir>` target).
- [Design] Jev cannot emit free text, so it cannot produce a file path, a grep pattern or any other command argument. The function-calling cookbook confirms that free text, numbers and dates receive no question and fall back to defaults. Argument generation must come from enumeration in the harness or from the LLM.
- [Design] Because users cannot fine-tune Jev, an RL course project cannot update Jev's weights. RL can only act on the controller around it (option set, option descriptions, state encoding, confidence thresholds, when to fall back) or on an open-weight surrogate (see Section 3 on HiddenLayer's conversion of Qwen3.8-27B).
- [Design] Pin a versioned model ID (`jev-1.13.0` or `jev-1.14.0`). Thresholds learned against `jev-latest` can silently break when the alias moves.
- [Design] Shell histories can approach the 32k per-question limit in long episodes, and the long-context mode trades accuracy for length by TypeSafe's own account, so the state should be truncated or summarized in code.

### Gaps
- No OpenRouter page loaded (`openrouter.ai/typesafe/jev` returned 404). A third-party TypingMind guide surfaced in search lists a "TypeSafe: Jev Router" model with ID `typesafe/jev-router`, but I did not fetch it and cannot confirm it.
- Numeric default rate limits are not published. Only the console shows them.
- Latency as a function of option count is not documented by TypeSafe or measured in the benchmark paper.
- Whether a short ID such as `jev-1.13` (without patch number) is accepted is not stated. The models page lists `jev-1.13.0`.
- Determinism (whether identical requests return identical probabilities) is not documented. The homepage lists "Is Jev deterministic?" as an FAQ question, but its answer did not appear in the fetched text, and the benchmark paper ran each request once.

## 2. What TypeSafe claims about architecture, RLCD, publications, founders and launch

### Takeaway
TypeSafe claims a new architecture, a non-autoregressive "parallel sampler" that produces all outputs in one query, and a new post-training method, RLCD, whose stated objective is epistemically honest probabilities. It has published no technical report, model card with architecture details, or paper describing RLCD's reward or loss. The company launched publicly on 15 September 2026 with a $40M seed round led by DCVC. Its founder and CEO is Diogo Almeida (ex-OpenAI), with co-founders Erik Gafni and Sasha Sheng.

### Cited Findings

**Architecture (all vendor claims)**
- The launch post says the stack consists of a new model architecture, a parallel sampler and a training method (RLCD). It contrasts Jev, which generates all outputs in a single query, with LLMs, which generate one token at a time conditioned on the last (vendor claim) — [TypeSafe launch blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- The post describes Jev as a function call that takes unstructured state and returns typed probabilistic decisions. It claims Jev never makes type errors and cannot hallucinate, and states that its 0% hallucination figure holds by design (schema matching is guaranteed) rather than being measured (vendor claim) — [TypeSafe launch blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- The homepage repeats "new architecture, a new sampler, and a new training algorithm" and claims "Zero Hallucinations", with no technical detail on any component (vendor claim) — [TypeSafe homepage](https://typesafe.ai/)
- The homepage FAQ lists "Is Jev just a smaller LLM?", "How can Jev be so fast and inexpensive?", "Are these prices temporary or subsidized?" and "Is Jev deterministic?", but the fetched page text did not contain their answers — [TypeSafe homepage](https://typesafe.ai/)

**RLCD (vendor claims, with no published mechanism)**
- Stated objective: answers with epistemically honest probabilities on System One tasks, so that higher confidence means higher accuracy, together with more consistent answers on similar inputs (vendor claim) — [TypeSafe launch blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- The documentation says System One models are trained so that their probabilities, optimized against outcomes, reflect uncertainty. It adds that calibration is measured across groups of predictions and does not guarantee that any single answer is correct — [TypeSafe docs, System One](https://docs.typesafe.ai/concepts/system-one)
- The homepage motivates the new algorithm by criticizing RLHF for mode dropping, overconfidence and lack of reliability. That is the only rationale given — [TypeSafe homepage](https://typesafe.ai/)
- The launch blog's FAQ includes "Why was a new training algorithm needed?", but the answer did not appear in the fetched content. The reward function and training procedure are not described — [TypeSafe launch blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- Independent confirmation that nothing is public: the benchmark paper states that Jev's size, architecture and training data are not public, and the term RLCD does not appear in its text — [arXiv 2609.37647 (HTML)](https://arxiv.org/html/2609.37647). HiddenLayer states that Jev's exact architecture has not been disclosed and that knowledge of its internals comes from black-box testing and open reimplementations — [HiddenLayer, "Jevil in the details"](https://www.hiddenlayer.com/research/system-one-model-security)
- A third-party paper, "Just Ask Jev", carries RLCD in its title and describes Jev as a model trained with RLCD, but cites no separate methods paper — [arXiv 2609.29429](https://arxiv.org/abs/2609.29429)

**Vendor benchmarks**
- Homepage headline: 193.6x faster and 444.6x cheaper, based on workflows for System One tasks. The displayed example compares TypeSafe at $0.000081 and 0.114 s with LLMs at $0.013880 and 8.566 s (vendor claim) — [TypeSafe homepage](https://typesafe.ai/)
- The homepage also claims a 238x lower input price than a named frontier model (vendor claim) — [TypeSafe homepage](https://typesafe.ai/)
- Launch blog: four workflow evaluations, with the reference answer taken as the average of GPT-6 Astra and another frontier model. The post claims 40x to 200x speedups on System One-shaped queries and concedes that the workflows were written by TypeSafe's own team and may be biased toward OpenAI and Anthropic models (vendor claim) — [TypeSafe launch blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- Launch blog demos: Doom at about 10 queries per second for about $7 per hour, and Wikiracing, choosing among hundreds to thousands of links (vendor claim) — [TypeSafe launch blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- Case study on the homepage (Jack & Jill): 88% lower candidate-screening cost and 2x speed, in production within 10 days (vendor claim) — [TypeSafe homepage](https://typesafe.ai/)

**Company, founders and launch**
- Launch date 15 September 2026. $40M seed round led by DCVC. San Francisco HQ. Founder and CEO Diogo Almeida, described as a former OpenAI researcher and co-inventor of RLHF. Co-founders Erik Gafni and Sasha Sheng. The model is named after the Jevons paradox. Dealroom cites a Business Wire press release as its source — [Dealroom news](https://dealroom.co/news/151032-typesafe-exits-stealth-with-40m-seed-to-build-ai-for-software-n)
- The launch post describes Almeida as having helped build instruction-following methods at OpenAI that became part of the research behind ChatGPT, and says the company spent two years in stealth — [TypeSafe launch blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- The blog post's text dates the announcement to 15 September 2026, while its page metadata says 28 October 2026, which suggests a later edit — [TypeSafe launch blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)

### Inferences
- The homepage's displayed example implies about 75x faster (8.566 s over 0.114 s) and about 171x cheaper ($0.013880 over $0.000081). Neither ratio matches the 193.6x and 444.6x headline, so the headline must come from a different aggregate, which the fetched page does not show.
- "Parallel sampler" plus "all outputs in a single query" is consistent with a single forward pass that scores every option (and every question) at once, as a classifier head over option encodings would. This reading is inference, since TypeSafe has not confirmed it.
- The "cannot hallucinate" claim is a statement about the output type (the answer is always one of the supplied options or a number in range), not about correctness. A confidently wrong Choice is still possible, and TypeSafe's own docs concede that calibration is group-level only.
- The description "co-creator of ChatGPT" in the task brief corresponds to the press release's "co-inventor of RLHF" and the blog's "helped build instruction-following methods at OpenAI". These are self-descriptions from TypeSafe material.

### Gaps
- RLCD's reward, loss, calibration target and training data are unpublished. A Towards AI article that, per search snippets, attributes a Brier-score proper-scoring-rule reward plus a batch calibration penalty to RLCD returned HTTP 403, and I could not verify whether it cites TypeSafe or reconstructs the method. Treat that description as unverified.
- No TypeSafe technical report, model card with architecture details, or arXiv paper was found.
- Search results reported larger follow-on financing (a Bloomberg report of about $870M at a $7.5B valuation led by Andreessen Horowitz, and a report in The Information of talks to raise more than $1B at above $10B). I did not fetch those pages, and the snippets disagree on whether a round closed.
- The New Stack's launch article (headline quotes TypeSafe calling sequential LLMs "totally useless for computers") loaded without its body, so its content is not used here.

## 3. Independent evaluations: benchmarks, calibration, security, and whether Jev is an LLM

### Takeaway
The Bonn/Lamarr benchmark paper (arXiv 2609.37647, `jev-1.13.0`) finds strong zero-shot classification and good pooled calibration (Choice ECE 0.028), but weak sequential decision-making, worse than Qwen3.8-27B on ALFWorld and TextWorld, with probabilities that do not separate right from wrong steps. Two security vendors find that Jev is steerable by content inside the state: HiddenLayer by ad-based prompt injection and TokenBreak perturbations, and Datadog by "counterfeit policy" text that cuts prompt-injection recall to below 10%. HiddenLayer argues System One models are language models with a different decoder, and TypeSafe says Jev is not an LLM.

### Cited Findings

**"Evaluating and Benchmarking the System One Model Jev" (arXiv 2609.37647)**
- Authors Tobias Deußer, Rajkumar Ramamurthy, Lorenz Sparrenberg and Rafet Sifa (University of Bonn, Lamarr Institute, with Fraunhofer IAIS and Accura AI Labs). Version 1 submitted 29 September 2026, version 2 on 29 October 2026, categories cs.CL and cs.AI. The model under test is `jev-1.13.0`, compared with the open-weight Qwen3.8-27B and Gemma-4-E4B — [arXiv 2609.37647 (abstract)](https://arxiv.org/abs/2609.37647); [HTML](https://arxiv.org/html/2609.37647)
- Scope and cost: 37 datasets evaluated zero-shot with one fixed template per task, 346,009 requests, 217.9 million input tokens for US$9.15, and US$9.40 for the whole study — [arXiv 2609.37647 (HTML)](https://arxiv.org/html/2609.37647)
- Accuracy: 95% to 99% on IMDB, SST-2, HellaSwag and ARC. Jev beat Qwen on 27 of 37 datasets, and Qwen's leads on the rest fall within bootstrap intervals. Jev beat Gemma on all 37. Threshold tuning raised micro-F1 on UNFAIR-ToS from 0.50 to 0.75. All three models degrade on low-resource languages, fine-grained or noisy labels, and rubric judgements — [arXiv 2609.37647 (abstract)](https://arxiv.org/abs/2609.37647)
- Calibration (Section 4.3): pooled Choice ECE 0.028 over 22 datasets and 279,925 answers (median per-dataset 0.028, unweighted mean 0.061). The mean top-option probability exceeds accuracy on 20 of 22 datasets. Noul ECE is 0.052 on eight binary datasets (mean P(yes) 0.465 against an observed yes-rate of 0.518). Multi-label Noul ECE is 0.168, with over-prediction of yes. Average ECE over 33 datasets is 0.074 for Jev, 0.075 for Qwen and 0.184 for Gemma. Reliability diagrams with 15 bins appear in Figure 2 — [arXiv 2609.37647 (HTML)](https://arxiv.org/html/2609.37647)
- Selective prediction at 50% coverage raises accuracy from 79.7% to 96.3% on Banking77, 81.5% to 98.2% on SIB-200, 73.9% to 86.9% on ANLI and 58.5% to 73.3% on Emotion — [arXiv 2609.37647 (HTML)](https://arxiv.org/html/2609.37647)
- Sequential decision protocol: each step is one request with the current state and a single Choice question whose options are the legal actions, and the most probable option is executed. Option counts were 15 to 44 (ALFWorld), 6 (BabyAI-Text), 3 to 72 (TextWorld), 2 (Blackjack) and 4 (FrozenLake). The ALFWorld state held the task, first and current observations, the full command and feedback history, and steps taken and left — [arXiv 2609.37647 (HTML)](https://arxiv.org/html/2609.37647)
- Sequential results: ALFWorld unseen tasks 35% completed against 54.5% for Qwen. TextWorld (90 games) 42% against 51.1% for Qwen. BabyAI-Text 21%. Blackjack optimal action in 90% of decisions. On FrozenLake Jev almost never moves away from the goal to avoid holes and often repeats actions that had no effect, failures it shares with Qwen — [arXiv 2609.37647 (abstract)](https://arxiv.org/abs/2609.37647)
- Per-task TextWorld and BabyAI results (Jev / Qwen / Gemma): coin collector level 10 at 0.50 / 0.90 / 0.20, coin collector level 110 at 0.10 / 0.80 / 0.00, treasure hunter level 5 at 0.80 / 0.70 / 0.50, cooking easy at 1.00 / 0.20 / 0.10. Jev re-enters dead ends listed in its own history and repeats actions with unchanged results — [arXiv 2609.37647 (HTML, appendix)](https://arxiv.org/html/2609.37647)
- Confidence does not track step correctness: on FrozenLake the mean top-option probability is 0.71 for correct and 0.72 for incorrect choices, and on BabyAI-Text 0.56 against 0.55. Across all FrozenLake variants the gap is at most 0.06. The authors conclude that the probabilities do not signal difficulty in these tasks — [arXiv 2609.37647 (HTML, appendix)](https://arxiv.org/html/2609.37647)
- Sequential calibration is poor: BabyAI-Text ECE 0.469 and Brier 1.132, improving to 0.387 and 1.028 with BALROG's instruction prompt. Multiclass Brier is 0.186 on Blackjack and 0.726 on TextWorld — [arXiv 2609.37647 (HTML)](https://arxiv.org/html/2609.37647)
- Request sensitivity on FrozenLake (500 fixed positions): base accuracy 0.320. A safety instruction raised it to 0.370 and mainly lowered confidence (ECE 0.398 to 0.170). Listing each option's landing tiles and probabilities in the request ("Outcomes" variant) raised accuracy to 0.624, which the authors say roughly doubles it while doing part of the work for the model. Non-slippery ice gave 0.838. At all 500 base positions Jev chose only "down" or "right" — [arXiv 2609.37647 (HTML, Appendix E)](https://arxiv.org/html/2609.37647)
- Stated limitations: one untuned template per dataset, open models scored without thinking, no proprietary generative models, one run per request (run-to-run variance not measured), and results that apply only to `jev-1.13.0` — [arXiv 2609.37647 (HTML)](https://arxiv.org/html/2609.37647)

**"Just Ask Jev" (arXiv 2609.29429), alignment-failure detection**
- Guo et al., submitted 24 September 2026, introduce RLCDAlignBench, which covers 10 failure types (including prompt injection, jailbreaks, deception and reward hacking) across 44 benchmarks and 5 target models. A single generic question reaches a median AUROC of 0.886 zero-shot. Jev matches the reference scorer's agreement with human labels and costs 63x less than LLM-judge scorers. Question wording matters little, while context fields matter more, mostly fields that encode the label — [arXiv 2609.29429](https://arxiv.org/abs/2609.29429)

**HiddenLayer security report (14 October 2026)**
- "Jevil in the details: Security implications of TypeSafe Jev and other System One models", by Kenneth Yeung and Kasimir Schulz — [HiddenLayer](https://www.hiddenlayer.com/research/system-one-model-security)
- Models tested: Jev through the API, an in-house System One model converted from Qwen3.8-27B by removing the normal decode process and adding a custom decode flow, the stock autoregressive Qwen3.8-27B, and gpt-6-luna through OpenAI's Decisions API. Fine-tuning the converted model was not required, but it improved accuracy on certain tasks — [HiddenLayer](https://www.hiddenlayer.com/research/system-one-model-security)
- Agent prompt injection: in a simulated checkout page driven through a "jev-ultrafast" harness, an attacker-controlled ad told the agent to do another task first. The converted model consistently clicked the ad despite a system prompt saying page text is untrusted. Jev behaved very similarly, gpt-6-luna made the same wrong decisions somewhat less consistently, and the stock autoregressive model was also derailed — [HiddenLayer](https://www.hiddenlayer.com/research/system-one-model-security)
- TokenBreak-style perturbations on 30 toxic prompts that every model initially flagged with very high scores: more perturbations with better targeting gave much higher attack success, and Jev and the converted model were vulnerable on many prompts. Numeric success rates appear only in images that the fetch could not read — [HiddenLayer](https://www.hiddenlayer.com/research/system-one-model-security)
- HiddenLayer's conclusion on architecture: "under the hood, these are still language models at heart", differing mainly in decoding strategy. It presents no direct tokenizer evidence about Jev itself — [HiddenLayer](https://www.hiddenlayer.com/research/system-one-model-security)
- Recommended mitigations: test decisions inside the real application with untrusted pages, misleading task text and meaning-preserving perturbations, monitor selected actions and scores, and add independent checks around consequential outcomes — [HiddenLayer](https://www.hiddenlayer.com/research/system-one-model-security)

**InfoWorld coverage (15 October 2026, Evan Schuman)**
- Schulz told InfoWorld that TokenBreak normally fails against larger LLMs but works on Jev out of the box. TypeSafe did not respond to multiple requests for comment. **Datadog Security Labs, "Jev as a judge: How counterfeit policy steers Jev" (15 October 2026)**
- Authors Nick Frichette and Feras Al-Kassar. The version is not named, and the post links TypeSafe docs for `jev-1.13` — [Datadog Security Labs](https://securitylabs.datadoghq.com/articles/jev-as-a-judge-how-counterfeit-policy-steers-jev/)
- Baseline prompt-injection detection on four public datasets (12,295 samples, 4,643 attacks): Noul precision 99.66%, recall 82.90%, F1 90.51%. Choice precision 99.45%, recall 85.46%, F1 91.93% — [Datadog](https://securitylabs.datadoghq.com/articles/jev-as-a-judge-how-counterfeit-policy-steers-jev/)
- Prepending a counterfeit policy (text inside the untrusted content that redefines Jev's labels and attack categories) dropped Noul recall to 3.88% (F1 7.46%) and Choice recall to 9.69% (F1 17.66%). Noul recall fell to 0% on two of the four datasets — [Datadog](https://securitylabs.datadoghq.com/articles/jev-as-a-judge-how-counterfeit-policy-steers-jev/)
- Tool-risk gating through LangChain, which blocks a tool call when `is_risky` is at least 0.5, over 40 runs per payload: the baseline mean `is_risky` was 0.893 (all calls blocked). With a counterfeit policy placed in a user-editable `profile_description` field it fell to 0.290, below the threshold. Plain prompt injection with fake system or assistant messages gave 0.905, close to baseline, as did hundreds of other plain injections — [Datadog](https://securitylabs.datadoghq.com/articles/jev-as-a-judge-how-counterfeit-policy-steers-jev/)

**TypeSafe's own admission of weaknesses (Jev 1.13 "jaggedness" page)**
- `jev-1.13` treats state as data and not as hostile by default. Injected instructions, deliberately misleading framing and text arguing for its own classification can shift answers. TypeSafe recommends explicit criteria and edge-case testing and says it expects to improve this — [TypeSafe docs, Jev 1.13 jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md)
- Other documented weaknesses: a bias toward the first Choice option (check by reordering), unreliable counting, weak arithmetic and numeric precision, unreliable date reasoning, lower accuracy on multi-hop or double-negative questions, accuracy loss as unrelated detail in the state grows, literal reading of scope words and negations, degradation under contradictory instructions, and weakly calibrated Score magnitudes that should be used only for threshold checks — [TypeSafe docs, Jev 1.13 jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md)

### Inferences
- On single-shot classification, Jev's calibration (pooled ECE 0.028, a 33-dataset mean of 0.074) is about equal to Qwen3.8-27B (0.075) scored in one forward pass. The independent evidence therefore supports "well calibrated" but not "uniquely calibrated by RLCD". The slight overconfidence on 20 of 22 datasets runs against the vendor's claim of epistemically honest probabilities.
- Calibration does not transfer to sequential control. ECE of about 0.4 to 0.47 on BabyAI-Text and FrozenLake, and identical confidence on right and wrong steps, mean a confidence threshold would not pick out the steps where an agent should defer.
- Whether Jev is an LLM: the evidence points to a transformer language model with a non-autoregressive scoring decoder. HiddenLayer shows that an open LLM converted this way behaves like Jev under attack, Jev bills in tokens with a 64k context, it is strongest in English, it shows first-option position bias, and TokenBreak transfers to it. None of this is proof, and TypeSafe disputes the label without publishing the architecture. Label this inference.
- The Datadog result has a specific shape: plain "ignore previous instructions" injections barely move Jev, while policy-like text that redefines the labels moves it a lot. The attack surface is the criteria semantics rather than an instruction-following channel.
- [Design] For a shell-agent controller, every command output (file contents, grep hits, README text) is untrusted state. A file containing text that redefines "dangerous" could push the flag-danger probability under threshold, as Datadog showed for `is_risky`. The flag-danger and abort options cannot serve as the security boundary, so a deterministic allow-list or sandbox must sit beneath them.
- [Design] The benchmark's protocol (one Choice over the legal actions per step, full history in state, argmax execution) is a ready-made baseline for the course project, and its failure modes (repeating no-effect actions, re-entering dead ends) are exactly what an RL-trained controller around Jev could target, for example by masking repeated no-op actions or adding outcome descriptions to options.
- [Design] The FrozenLake "Outcomes" result suggests that putting each command's expected effect in its Choice description could raise step accuracy substantially. The authors caution that this hands part of the reasoning to the prompt.
- [Design] The documented first-option bias calls for randomized or fixed-and-reported option ordering across rollouts, and for an ordering ablation.

### Gaps
- No independent evaluation of `jev-1.14.0` was found. All third-party numbers concern `jev-1.13.0` or an unnamed version.
- HiddenLayer's numeric attack success rates are only in images that the fetch could not read.
- A search snippet attributed 86.7% accuracy on Belebele across 122 languages to the benchmark paper, and another attributed a median AUROC of 0.905 with a within-benchmark calibration gap of 0.125 to "Just Ask Jev". Neither appeared in the pages I fetched (the "Just Ask Jev" abstract gives a median AUROC of 0.886), so both are unverified.
- A radiology-report factuality paper ("Can Jev Judge Radiology Reports?", arXiv 2609.27607) surfaced in search but was not fetched.
- The Hacker News launch thread was not fetched. Secondary blogs put it near 1,900 points and 500 comments, with criticism focused on the "cannot hallucinate" claim, but I did not verify this against the thread.
- No third-party latency study beyond the benchmark paper's 0.36 s mean was found, and no study measures latency against option count.

## 4. Uses TypeSafe and integrators promote, including agent tool selection and guardrails

### Takeaway
TypeSafe pitches Jev as "smart if-statements" for classification, routing, scoring, extraction and branching, for map-reduce over large datasets, for real-time decisions near 100 ms, and for verification (judging, guardrails, jailbreak detection). Its docs include cookbooks for function calling, skill suggestion and LLM guardrails, and patterns for confidence-gated routing. Integrators (Vercel, AgentScope, LangChain via Datadog's test) wire Jev in as a tool selector, tool-call risk gate or confidence-gated front end that escalates to an LLM.

### Cited Findings
- Promoted uses: classification, routing, scoring, extraction and branching inside software, map-reduce over large datasets, real-time applications at roughly 100 ms, verification (scoring, judging, guardrails, detecting jailbreaks in prompts, reasoning traces and outputs), and agents, where the post names hallucinated tool calls as a problem but does not detail a tool-selection design (vendor claims) — [TypeSafe launch blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- The documentation lists cookbooks for function calling, skill suggestion, guardrails for LLMs, citation checking, RAG passage classification, hierarchical classification, re-ranking, an "SDE cascade", and self-consistency for choices and nouls. It also lists patterns named speculative fan-out, confidence-gated routing, composite scoring and intent routing, and a page on using Jev with coding agents — [TypeSafe docs index](https://docs.typesafe.ai/llms.txt)
- Function-calling cookbook: one request per user command carries the tool choice (a Choice question `__tool__`) and every function's arguments, with 54 questions per command for an assistant with ten functions and 28 fillable arguments. Arguments are typed as Choice (a `Literal`), Set (one Noul per member of a `list[Literal]`) or Flag (`bool`). Free text, numbers and dates get no question, so the function's default applies. The reported `confidence` is that of the least certain judgement in the call. The cookbook gives no confidence threshold and no fallback for low tool confidence — [TypeSafe cookbook, Function calling](https://docs.typesafe.ai/cookbooks/function_calling.md)
- Choice guidance: include an "other" or "none of the above" option when inputs may not fit (TypeSafe notes this may work poorly and suggests a companion Noul asking whether any option applies). For deep hierarchies, chain Choice questions level by level, optionally with beam search over the probabilities. In the docs' ticket example, a confidence of 0.42 routes the ticket to manual triage — [TypeSafe docs, Choice](https://docs.typesafe.ai/primitives/choice)
- Thresholds suggested by TypeSafe: three bands (act, act with caution, do not act), with routing to a human below 0.5 and above 0.9 required before an unconfirmed high-stakes action. For Noul, 0.7 for yes and 0.3 for no as a starting point. TypeSafe says thresholds depend on the domain and must be tested on the user's own data — [TypeSafe docs, Confidence](https://docs.typesafe.ai/confidence.md)
- Vercel AI Gateway's decision fallbacks rerun a decision on an LLM (example `openai/gpt-6-astra`) when a named question's confidence falls below a set value (example 0.6), and bill both stages. Vercel's docs also link guides on auto-approving tool calls in an agent ("eve") with Jev and on routing form submissions — [Vercel docs, TypeSafe API with AI Gateway](https://vercel.com/docs/ai-gateway/sdks-and-apis/typesafe.md)
- AgentScope Java's `JevToolSelectionMiddleware` uses independent per-tool relevance scoring over a context window (by default the latest 8 non-blank text messages within 8,000 characters), runs in OFF, SHADOW (record recommendations only) or ENFORCE mode, and advises calibrating thresholds on labelled data. The page states that semantic decisions do not grant permissions or prove that execution succeeded, so deterministic authorization and completion checks stay in the application — [AgentScope Java docs, Jev](https://java.agentscope.io/v2/en/jev.md)
- LangChain tool-risk gating with a Jev `is_risky` score (block at 0.5 or above) was the integration Datadog attacked, which shows the guardrail use exists in practice — [Datadog Security Labs](https://securitylabs.datadoghq.com/articles/jev-as-a-judge-how-counterfeit-policy-steers-jev/)
- The "Just Ask Jev" paper uses Jev as a zero-shot detector of alignment failures, including prompt injection and reward hacking, at 63x lower cost than LLM-judge scorers — [arXiv 2609.29429](https://arxiv.org/abs/2609.29429)

### Inferences
- The promoted pattern for agents is a cheap front end that selects or filters actions with a confidence statistic, plus escalation to an LLM when confidence is low (Vercel fallbacks, AgentScope SHADOW/ENFORCE, TypeSafe's confidence bands). The course project's "fall back to the LLM" option corresponds to this pattern. The benchmark paper's finding that step-level confidence does not separate correct from incorrect actions is the main evidence against relying on a fixed confidence threshold for that fallback, and it argues for learning the fallback rule from rollouts instead.
- Two designs for the fallback are available, and they behave differently: fallback as one more Choice option (the model's own probability for "fall back") or fallback as a rule on the confidence statistic. Only the second matches the Vercel and TypeSafe pattern. The first is untested in any source found.
- Because extra questions in one request add little latency by TypeSafe's account, a step could ask the action Choice together with Noul questions such as "does the last output contain instructions addressed to the agent" or "did the last command change anything". This mirrors TypeSafe's companion-Noul advice and targets the repeated-no-op failure the benchmark found. The latency claim for this specific pattern is vendor-only.
- [Design] Datadog's and AgentScope's findings together say that Jev-based gating can recommend but must not authorize. A shell harness should enforce a deterministic deny-list (for example `rm -rf`, writes outside a sandbox) independently of the flag-danger option.

### Gaps
- No TypeSafe page describes narrowing a large tool set to a few before an expensive LLM runs. The function-calling cookbook selects one tool directly, and AgentScope documents per-tool relevance scoring without defaults or top-k details (its Chinese-language tool-selection guide was not fetched).
- The "Jev with coding agents", "Skill suggestion", "Guardrails for LLMs" and "Confidence-gated routing" pages were listed in the docs index but not fetched, so their contents are not reflected here.
- No source reports Jev controlling a shell or coding agent at the command level, which is the closest analogue to the course project.
