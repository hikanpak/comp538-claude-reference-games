# Open Jev clones make calibrated shell control trainable

Jev, released by TypeSafe AI on 15 September 2026, is a closed, hosted "System One" model. It reads a text or JSON state and a set of typed questions, and it returns a probability distribution for each question instead of generated text. Access runs only through TypeSafe's `POST /v1/systemone` API and Vercel AI Gateway, at **$0.042 per million input tokens with output free**, and **no customer can fine-tune it**. RLCD, TypeSafe's Reinforcement Learning for Calibrated Decisions, is public only as a name and a goal, so every account of its reward, the popular proper-scoring-rule reading included, is commentator inference. The one broad independent evaluation (University of Bonn and Lamarr Institute, `jev-1.13.0`) finds a **pooled Choice ECE of 0.028, level with the open Qwen3.8-27B**. It also finds **35% completion on unseen ALFWorld tasks against Qwen's 54.5%**, and step confidences that are the same for right and wrong actions. HiddenLayer and Datadog show that text inside the state steers its decisions, and Datadog's counterfeit policies cut prompt-injection recall **below 10%**. Since Jev's weights are out of reach, the COMP538 controller has to be an open look-alike, and Mapika's decider-2b is the best base because it is the only open checkpoint already shaped by outcome-reward, calibration-aware RL on agent environments. The evidence supports supervised log loss with a fitted temperature as the floor, then RL on episode outcomes that charge for LLM calls, danger and abort, with a bounded Brier term, a leave-one-out baseline, a KL anchor and a temperature refit. No published system puts a typed decision model in charge of a shell agent with abort, danger and LLM-fallback actions, so the design is new and its multi-step behavior is untested.

## Jev answers typed questions through a closed API at $0.042 per million tokens

Throughout this report, a figure is a vendor claim when it comes from TypeSafe, self-reported when a third-party project states it in its own README, model card or paper without reproduction, and independent when a party with no stake in the model measured it. Academic results and the report's own inferences carry the status words Proven, Heuristic, Empirical and Open.

TypeSafe defines a System One model as one that evaluates a state and returns typed answers with probabilities, and never writes replies, code or explanations ([TypeSafe docs](https://docs.typesafe.ai/concepts/system-one)). A request carries a model ID, a `state` (string, object or array) and at least one named question. Each question uses one of four primitives ([TypeSafe API reference](https://docs.typesafe.ai/api/system-one.md)).

| Primitive | The developer supplies | Jev returns |
|---|---|---|
| Choice | 1 to 255 named options, descriptions optional | the most probable option, a `confidence`, and a probability per option |
| Score | an ordered rubric of 1 to 10 level descriptions | the probability-weighted expected level (possibly fractional), `confidence`, `legend` and probabilities |
| Noul | an optional true/false criterion | the probability of true, with no confidence field |
| Box | an image and instructions, behind the `TypeSafe-Danger-Zone-Images` header | box coordinates as fractions of the image, and a confidence that may be null |

The Choice `confidence` rescales the top probability so that a uniform distribution scores 0 and a point mass scores 1. It ignores how the remaining mass is spread, so (0.6, 0.3, 0.1) and (0.6, 0.2, 0.2) both score 0.4, and TypeSafe calls it one reasonable summary and **does not claim it is calibrated** ([TypeSafe docs, Confidence](https://docs.typesafe.ai/confidence.md)). Calibration of the `probabilities` vector and calibration of the `confidence` scalar are therefore separate claims. The CMU survey by Li, Miao, Krishnan and Padman warns that the scalar is not a correctness probability until it is validated on the user's own data ([Li et al. survey](https://yubol-bobo.github.io/rlcd-survey/pdf/calibration-aware-rl-survey.pdf)). Choice is single-select, and the model never sees the question ID, which only keys the answer ([TypeSafe docs, Choice](https://docs.typesafe.ai/primitives/choice)).

Requests go to `https://api.typesafe.ai` with a bearer key, directly or through the official Python and JavaScript SDKs, and the response names the versioned model that answered ([TypeSafe API reference](https://docs.typesafe.ai/api/system-one.md)). `jev-1.14.0` has been the newest release since 14 October 2026, and `jev-1.13.0` is the previous one. The aliases `jev-latest` and `jev-preview` both moved to 1.14.0 on release, and TypeSafe itself advises a versioned ID wherever confidence thresholds were tuned ([TypeSafe docs, Models](https://docs.typesafe.ai/models)). A request may hold 64k tokens, and the state plus any one question 32k. A long-context header raises both limits to 262k at the same price, slower and less accurate by TypeSafe's own account. Rate limits are set per organization and unpublished, English gives the best accuracy, and **all accounts share one set of RLCD-trained weights that is never fine-tuned per customer** ([TypeSafe docs, Models](https://docs.typesafe.ai/models)). Vercel AI Gateway resells Jev as `typesafe-ai/jev` at list price, and its worked example bills 275 input tokens at $0.00001155. The gateway adds decision fallbacks that rerun an uncertain answer on an LLM, for example `openai/gpt-6-astra` when a named question's confidence drops below 0.6, and the LLM's answer then carries confidence 0 and empty probabilities ([Vercel docs](https://vercel.com/docs/ai-gateway/sdks-and-apis/typesafe.md)). An OpenRouter listing could not be confirmed, because its URL returned HTTP 404.

On price the vendor and the independent record agree. TypeSafe lists $42 per billion input tokens with output free ([TypeSafe docs, Models](https://docs.typesafe.ai/models)), and the Bonn evaluation paid $9.15 for 217.9 million input tokens, the same rate ([arXiv 2609.37647](https://arxiv.org/html/2609.37647)). On speed they diverge. The launch post claims 70 to 500 ms end to end from US West Coast laptops, and the press release summarized by Dealroom claims under 100 ms, both vendor claims ([TypeSafe launch blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev), [Dealroom](https://dealroom.co/news/151032-typesafe-exits-stealth-with-40m-seed-to-build-ai-for-software-n)). The Bonn authors measured **a mean of 0.36 s per request at 32 concurrent connections**, network included ([arXiv 2609.37647](https://arxiv.org/html/2609.37647)). The homepage headline of 193.6x faster and 444.6x cheaper than LLMs is a vendor claim, and the example displayed beside it implies about 75x and 171x, so the headline rests on an aggregate the page does not show ([TypeSafe homepage](https://typesafe.ai/)). The launch post's 40x to 200x speedups come from four workflows written by TypeSafe's own team, scored against reference answers averaged from GPT-6 Astra and another frontier model, and the post concedes that the workflows may favor those models ([TypeSafe launch blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)).

TypeSafe promotes Jev for classification, routing, scoring, branching, map-reduce over datasets, verification, guardrails and agents ([TypeSafe launch blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)). Its function-calling cookbook packs the tool choice and every enumerable argument into one request. Free text, numbers and dates get no question, so the function's default applies, and the reported confidence is that of the least certain judgement ([TypeSafe cookbook](https://docs.typesafe.ai/cookbooks/function_calling.md)). The threshold guidance has three bands, routing to a human below 0.5 and requiring more than 0.9 before an unconfirmed high-stakes action, with 0.7 and 0.3 as starting Noul thresholds ([TypeSafe docs, Confidence](https://docs.typesafe.ai/confidence.md)). TypeSafe's weakness page for `jev-1.13` admits that the model treats state as data rather than as hostile, so injected instructions and text arguing for its own classification can shift answers. The page also lists a **bias toward the first Choice option**, unreliable counting, arithmetic and date reasoning, accuracy loss as unrelated detail accumulates, and weakly calibrated Score magnitudes ([TypeSafe docs, Jev 1.13 jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md)). For a shell controller the binding constraint is that Jev cannot write a path, a pattern or any other argument, so the harness must enumerate each argument or the LLM must write it.

## RLCD is published as a name and a goal, not as a method

TypeSafe left two years of stealth on 15 September 2026 with a $40M seed round led by DCVC. Its material describes founder and CEO Diogo Almeida as a former OpenAI researcher and co-inventor of RLHF, and names Erik Gafni and Sasha Sheng as co-founders ([Dealroom](https://dealroom.co/news/151032-typesafe-exits-stealth-with-40m-seed-to-build-ai-for-software-n), [TypeSafe launch blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)). The launch post introduces RLCD as a new training method whose target is calibrated decisions, meaning answers with "epistemically honest probabilities". It places RLCD beside RLHF, which optimizes human preference, and RLVR, which optimizes programmatically verifiable rewards ([TypeSafe launch blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)). The ML primer adds that RLCD trains the model to return decisions and calibrated probabilities instead of text, and that calibration describes groups of predictions, not single answers ([TypeSafe ML primer](https://docs.typesafe.ai/introduction/machine-learning-primer)). **No reward, loss, scoring rule, dataset, step count or calibration metric has been published**, and the launch post defers the reliability argument to a later date ([TypeSafe launch blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)).

The architecture is described only as a new model, a parallel sampler that produces all outputs in one query, and RLCD. The claim of zero hallucinations holds by construction, because the answer always matches the supplied schema, and not by measurement (vendor claim) ([TypeSafe launch blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)). A confidently wrong Choice remains possible, as the agent-platform vendor Beam and an independent consultant quoted by InfoWorld both point out ([Beam](https://beam.ai/agentic-insights/jev-typesafe-ai-agents), [InfoWorld](https://www.infoworld.com/article/4236103/typesafes-jev-even-more-susceptible-to-attack-than-llms-says-security-vendor.html)).

Every outside party that looked found the same absence. The Bonn benchmark paper states that Jev's size, architecture and training data are not public, and it never mentions RLCD ([arXiv 2609.37647](https://arxiv.org/html/2609.37647)). HiddenLayer says that knowledge of Jev's internals comes only from black-box tests and open reimplementations ([HiddenLayer](https://www.hiddenlayer.com/research/system-one-model-security)). systemonemodels.org found zero arXiv results for the phrase on 20 September 2026 and describes the public record as the name and the goal, without method, data or code ([systemonemodels.org](https://systemonemodels.org/guides/rlcd-explained/)). The Li et al. survey concludes that the published material sets a design direction but does not identify the recipe with any open algorithm ([Li et al. survey](https://yubol-bobo.github.io/rlcd-survey/pdf/calibration-aware-rl-survey.pdf)). dsebastien.net reports Almeida describing RLCD on the Latent Space podcast as a new task more than a specific algorithm, and as novel and unpublished ([dsebastien.net](https://www.dsebastien.net/reinforcement-learning-for-calibrated-decisions-rlcd/)).

The popular account, in which RLCD rewards a proper scoring rule such as the Brier score plus a batch calibration penalty, traces to a Towards AI article, which cites no TypeSafe source and could be read only as a search snippet ([Towards AI](https://pub.towardsai.net/rlcd-reinforcement-learning-for-calibrated-decisions-e528daf3591d)). dsebastien.net labels the competing accounts as guesses. Archer Hume proposed a strictly proper scoring rule on the output distribution after about 10,000 API calls, and Di Zhang proposed a schema-conditioned Plackett-Luce objective with a Brier term ([dsebastien.net](https://www.dsebastien.net/reinforcement-learning-for-calibrated-decisions-rlcd/)). The same page asks whether "reinforcement learning" is even the right label when outcomes are known and supervised cross-entropy would do. The proper-scoring reading is plausible but not distinguishable from the alternatives, because supervised log loss on fixed labels is itself a proper scoring rule, and nothing TypeSafe published separates RLCD from supervised calibration training (Heuristic). Almeida's task framing points the same way, so the course project loses nothing by defining its own objective instead of reconstructing TypeSafe's.

Three unrelated expansions of the acronym circulate, and only the first concerns Jev.

| Expansion | Source | What it denotes | Relation to Jev |
|---|---|---|---|
| Reinforcement Learning for Calibrated Decisions | TypeSafe launch post, 15 September 2026 | the unpublished post-training method behind Jev | Jev's training method (vendor claim) |
| Reinforcement Learning from Contrastive Distillation | Yang, Klein, Celikyilmaz, Peng and Tian, [arXiv 2307.12950](https://arxiv.org/abs/2307.12950v2) (2023) | preference pairs built from contrasting prompts, which align a model to written principles without human labels and beat RLAIF and context distillation on harmlessness, helpfulness and story outlines | unrelated, and three years older |
| Cloudflare's RLCD stage | Cloudflare's Clef launch post, 1 October 2026 | a training stage inside Clef, a decision model post-trained from Qwen3.8-27B | does not match TypeSafe's method according to [systemonemodels.org](https://systemonemodels.org/guides/rlcd-explained/), not verified on a Cloudflare page |

Several projects borrow the first meaning without reproducing it. Laya calls one loss term `rlcd_loss` ([Laya train.py](https://github.com/NandhaKishorM/laya/blob/main/laya/train.py)). StartLux names its reasoning recipe RLCD², reinforcement learning for calibrated deliberative decisions, in arXiv 2610.17309, which was not read ([StartLux README](https://github.com/StartLuxLabs/StartLux-Decision)). *Just Ask Jev* names its alignment benchmark RLCDAlignBench ([arXiv 2609.29429](https://arxiv.org/abs/2609.29429)). Hugging Face models created on 16 to 19 September with "rlcd" in their names document no reproduction, and `TaylorAI/Llama-3B-RLCD-SFT` predates Jev and belongs to the contrastive-distillation meaning ([systemonemodels.org](https://systemonemodels.org/guides/rlcd-explained/)).

## Independent tests confirm single-question calibration and expose sequential and injection failures

Set side by side, the vendor's claims and the independent measurements agree on price and single-question calibration, and they part ways wherever sequences or adversarial text enter.

| Property | TypeSafe's claim | Independent measurement |
|---|---|---|
| Price | $0.042 per million input tokens | $9.15 for 217.9M tokens in the Bonn study, the same rate |
| Latency | 70 to 500 ms (blog), under 100 ms (press release) | 0.36 s mean at 32 concurrent requests |
| Calibration | higher confidence means higher accuracy, no metric given | pooled Choice ECE 0.028, 33-dataset mean 0.074 against Qwen3.8-27B's 0.075, overconfident on 20 of 22 datasets |
| Sequential control | not claimed beyond Doom and Wikiracing demos | ALFWorld 35% against Qwen's 54.5%, step confidence 0.71 when right and 0.72 when wrong |
| Hallucination | zero, by design | true of the output type only, wrong options remain possible |
| Robustness to state content | admitted as a weakness in the 1.13 docs | counterfeit policy cuts injection recall to 3.88%, an ad injection derails an agent |

The only broad independent benchmark is *Evaluating and Benchmarking the System One Model Jev* by Deußer, Ramamurthy, Sparrenberg and Sifa (University of Bonn, Lamarr Institute, Fraunhofer IAIS and Accura AI Labs), posted on 29 September 2026 and revised on 29 October. It pins `jev-1.13.0`, compares it with the open Qwen3.8-27B and Gemma-4-E4B on 37 datasets zero-shot with one fixed template per task, and spent **$9.40 on 346,009 requests** ([arXiv 2609.37647](https://arxiv.org/abs/2609.37647)). Jev reached 95% to 99% on IMDB, SST-2, HellaSwag and ARC. It beat Qwen on 27 of 37 datasets, with Qwen's leads on the rest inside bootstrap intervals, and beat Gemma on all 37. Pooled Choice ECE was **0.028 over 22 datasets and 279,925 answers**, Noul ECE was 0.052 on eight binary datasets, and multi-label Noul ECE was 0.168 with over-prediction of yes. The 33-dataset average ECE was **0.074 for Jev, 0.075 for Qwen and 0.184 for Gemma**, and Jev's mean top probability exceeded its accuracy on 20 of 22 datasets ([arXiv 2609.37647 HTML](https://arxiv.org/html/2609.37647)). Selective prediction works on these tasks, since answering only the more confident half raised accuracy from 79.7% to 96.3% on Banking77 and from 73.9% to 86.9% on ANLI. The evidence supports well-calibrated single questions (Empirical) but not calibration unique to RLCD, since an open model read in one forward pass matched it, and the mild systematic overconfidence runs against the vendor's honesty claim.

Sequential control is where Jev falls behind. The authors sent one request per step, with the full history in the state and a single Choice over the legal actions, and executed the most probable option, with 15 to 44 options on ALFWorld and 3 to 72 on TextWorld ([arXiv 2609.37647 HTML](https://arxiv.org/html/2609.37647)). Jev completed **35% of unseen ALFWorld tasks against 54.5% for Qwen**, 42% of 90 TextWorld games against 51.1%, and 21% on BabyAI-Text, while choosing the optimal Blackjack action 90% of the time ([arXiv 2609.37647](https://arxiv.org/abs/2609.37647)). On the TextWorld coin collector at level 110 it scored 0.10 against Qwen's 0.80, although it solved the easy cooking task that Qwen mostly failed. The logs show it re-entering dead ends listed in its own history and repeating actions whose results did not change. **Its confidence did not track step correctness**, with a mean top probability of 0.71 on correct and 0.72 on incorrect FrozenLake moves, 0.56 against 0.55 on BabyAI-Text, and a BabyAI-Text ECE of 0.469 ([arXiv 2609.37647 HTML](https://arxiv.org/html/2609.37647)). Request design moved accuracy a lot. On 500 fixed FrozenLake positions a safety instruction raised accuracy from 0.320 to 0.370, mostly by lowering confidence, and listing each option's outcomes in the request raised it to 0.624, which the authors note does part of the reasoning for the model. At every one of the 500 base positions Jev chose only down or right. The authors name one untuned template per dataset, one run per request and validity for `jev-1.13.0` only as limitations, and **no independent evaluation of `jev-1.14.0` exists**.

A second study uses Jev as a judge rather than an actor. *Just Ask Jev* (Guo et al.) builds RLCDAlignBench, covering ten alignment-failure types including prompt injection, deception and reward hacking across 44 benchmarks and five target models. A single generic question asked zero-shot reaches a median AUROC of 0.886, agreement with human labels matches the reference scorer, and the cost is 63 times below LLM-judge scorers. Context fields matter more than question wording, mostly fields that encode the label ([arXiv 2609.29429](https://arxiv.org/abs/2609.29429)).

HiddenLayer's report of 14 October 2026, by Kenneth Yeung and Kasimir Schulz, tested Jev, an in-house System One model converted from Qwen3.8-27B by replacing its decoding, the stock autoregressive Qwen, and OpenAI's gpt-6-luna through the Decisions API. In a simulated checkout page, an attacker-controlled ad told the agent to do another task first. The converted model clicked it consistently despite a system prompt calling page text untrusted, **Jev behaved very similarly**, gpt-6-luna erred somewhat less consistently, and the stock model was also derailed. TokenBreak-style perturbations of 30 toxic prompts defeated Jev and the converted model on many prompts, with success rates shown only in images ([HiddenLayer](https://www.hiddenlayer.com/research/system-one-model-security)). Schulz told InfoWorld that TokenBreak usually fails on larger LLMs but works on Jev out of the box, and TypeSafe did not answer requests for comment. An IDC analyst called the method sound, a Gartner analyst called some reports premature, and the article notes that a security vendor finding a new product insecure is somewhat self-serving ([InfoWorld](https://www.infoworld.com/article/4236103/typesafes-jev-even-more-susceptible-to-attack-than-llms-says-security-vendor.html)).

Datadog Security Labs (Nick Frichette and Feras Al-Kassar, 15 October 2026) measured the sharper failure. On four public prompt-injection datasets with 12,295 samples, Jev's Noul detector reached 99.66% precision and 82.90% recall, and its Choice detector 85.46% recall. **Prepending a counterfeit policy, text inside the untrusted content that redefines Jev's labels, cut Noul recall to 3.88% and Choice recall to 9.69%**, with 0% on two datasets. In a LangChain gate that blocks a tool call when `is_risky` reaches 0.5, the mean score over 40 runs fell from 0.893 to 0.290 when the counterfeit policy sat in a user-editable profile field. Plain injections with fake system messages left it at 0.905 ([Datadog Security Labs](https://securitylabs.datadoghq.com/articles/jev-as-a-judge-how-counterfeit-policy-steers-jev/)). The attack surface is the meaning of the criteria rather than an instruction-following channel (Empirical, for the version the post links as `jev-1.13`).

The only measurement on shell commands comes from a one-person project. tiny-bouncer screened a 265-command battery inside the OpenCode harness. Jev reached a false-negative rate of 0.000 and a false-positive rate of 0.138 (three-way accuracy 0.845), the open Strands Decider 2B run locally reached 0.000 and 0.415 (0.766), and Jev alone met the project's gates (self-reported, independent of TypeSafe) ([tiny-bouncer findings](https://github.com/radupopescu/tiny-bouncer/blob/main/doc/findings.md)). Two further black-box calibration figures, ECE 0.031 on MMLU and 0.107 on synthetic support tickets, appear only secondhand on dsebastien.net, which also relays the critique that individually calibrated judgements do not compose into calibrated workflows ([dsebastien.net](https://www.dsebastien.net/reinforcement-learning-for-calibrated-decisions-rlcd/)).

TypeSafe says Jev is not an LLM, and HiddenLayer concludes that System One models remain language models that differ mainly in decoding ([InfoWorld](https://www.infoworld.com/article/4236103/typesafes-jev-even-more-susceptible-to-attack-than-llms-says-security-vendor.html), [HiddenLayer](https://www.hiddenlayer.com/research/system-one-model-security)). The circumstantial record favors HiddenLayer. Jev bills in tokens with a 64k context, works best in English, shows first-option bias and falls to TokenBreak, and an open LLM converted to one-pass decoding fails the same way under attack. None of it is proof, and the label stays an inference until TypeSafe publishes the architecture.

## Fifty open look-alikes copy the interface, and few copy the training

The open ecosystem is large and young. The awesome-decision-models list (CC0, 681 stars) carries about 50 open models and 10 training-free techniques, all from after mid-September 2026. It warns that each score is reported by its own project on a benchmark of that project's choosing, so scores are not comparable across entries ([awesome-decision-models](https://github.com/AnotiaWang/awesome-decision-models)). No project reproduces Jev's training, because there is nothing published to reproduce. Projects copy the interface (state plus Choice, Score and Noul questions, often at a wire-compatible `POST /v1/systemone`), and a minority also copy Jev's outputs by distillation. They fall into three groups. Trained one-pass models with released training code include decider, Kev, Strands Decider, Jeeves, Laya, NanoJev and AgentJev. Trained models without training code include JEV-27B, OpenThai-SystemOne, opendecider, OpenSysOne and openjev/openjev. Training-free readouts over a frozen LLM include LitJev, LLM2Jev, AnyJev and SemIf.

Several names that circulate as reproductions are something else on inspection. LitJev calls itself a hypothesis-based reproduction from public information, but it is a training-free readout that sums each option's token log-probabilities on a Qwen checkpoint (Qwen3.8-27B by default), and it states that its probabilities are not calibrated by default ([LitJev](https://github.com/zhengxuyu/litjev)). OpenSysOne is a 16.5M-parameter adapter on Qwen3-4B-Instruct-2507 in a custom checkpoint format. Its reproduction guide covers only inference from a hard-coded local path, and its selected scorer is slower than its own base verifier on all 12 profiled workloads ([OpenSysOne card](https://huggingface.co/andyshu/opensysone), [reproduce.md](https://huggingface.co/andyshu/opensysone/blob/main/docs/reproduce.md)). SiliconLabAI/OpenJev is a six-commit Node playground with no model of its own, whose `decider` backend serves Mapika's decider-2b, and the name OpenJev belongs to at least four unrelated projects besides the OpenJev-RLCD paper ([SiliconLabAI/OpenJev](https://github.com/SiliconLabAI/OpenJev), [awesome-decision-models](https://github.com/AnotiaWang/awesome-decision-models)). autotrust/JEV-27B freezes Qwen3.8-27B and trains a LoRA and a 24-slot head by KL distillation from Jev 1.13's output distributions on a public 741k-row corpus. Its **self-reported ECE of 0.0009 therefore measures agreement with Jev, not calibration against ground truth**. The same card reports Brier 0.25 on the typed-decisions set, answers that change with option order about 7% of the time, and teacher mistakes copied into the student ([JEV-27B card](https://huggingface.co/autotrust/JEV-27B)). opendecider and OpenThai-SystemOne release weights without training code ([opendecider](https://github.com/manjunathshiva/opendecider), [OpenThai-SystemOne](https://huggingface.co/iapp/OpenThai-SystemOne)).

Mapika's decider is the closest match to the course project. Its models fine-tune Qwen3.5 base checkpoints under Apache-2.0, decider-2b on Qwen3.5-2B-Base with a 32k context and decider-4b on Qwen3.5-4B-Base. One forward pass reads one label token per option at an answer slot for up to 255 options, and the server speaks TypeSafe's wire format so the official SDKs work unchanged ([decider README](https://github.com/Mapika/decider)). The supervised stage is released, with data builders for about 95 public datasets plus labels from a local Qwen3.5-27B teacher, temperature fitting, and an evaluator for accuracy, NLL, Brier, ECE and AURC. Nothing was distilled from Jev, and one epoch takes 5.3 h on one GH200. **decider-2b v10 is the only open checkpoint produced by outcome-reward, calibration-aware RL on agent environments.** The RL stage ran 384 optimizer steps on the served softmax itself, with rewards only from outcomes in 16 live MiniWoB++ click tasks, exact 4x4 minesweeper, a slippery 5x5 grid and draws from bags of known composition ([decider RL.md](https://github.com/Mapika/decider/blob/main/docs/RL.md)). Its loss has four terms. A PPO actor term uses a leave-one-replicate-out baseline over four repeats, and a belief term log-scores the model's prediction of what happens next against the exact law in two option orders. A KL term enforces consistency across option orders and layouts, and a retention KL to the supervised v8 checkpoint triggers fallback steps when drift exceeds set limits. The peak learning rate was 1e-6, six gates against v8 decided acceptance, and a first attempt at 2e-6 drifted and failed. Self-reported results are browser-task success rising from 83.0% to 93.2%, six never-rewarded tasks from 72.9% to 91.7%, belief excess falling from 0.473 to 0.219 nats, and a general fixture slipping from 64.1% to 63.3%. **The RL code is not released**, because it needs a live Chrome and four GPUs, although the package ships ten text games with imitation and PPO. decider's README quotes third-party standings that put decider-2b at 28.97 on the chance-corrected Decision Index against Jev's 57.91, and a top-label ECE of 0.31 on JevBench hard items at v10. It also admits that rules written into the question are not followed at 2B, where a one-sentence question scores 0.67 and a paragraph of rules 0.24 ([decider README](https://github.com/Mapika/decider)).

Kev (jaredpalmer/kev, Apache-2.0, 9,751 stars) attaches a rank-16 LoRA and a small pointer head to Qwen3.5 base models at 0.8B, 4B and 9B, scoring each option's closing-tag hidden state against the question's. It trains with cross-entropy on 10,000 examples from ten public datasets plus generated policy and rule examples, used no Jev outputs, stores one temperature per checkpoint, and continues a released adapter through `--init_from` ([Kev README](https://github.com/jaredpalmer/kev)). Kev-0.8B trains in about 20 minutes per stage on one H100 and fits a 4 GB card at batch 1. On held-out new sources Kev-4B reaches 0.817 development accuracy and Brier 0.269, against Jev's 0.857 and 0.211 (self-reported). Strands Decider 2B (AWS Strands Labs, Apache-2.0) replaces the Qwen3.5-2B-Base LM head with a pointer head of about one million parameters that has **no per-option parameters, so it cannot learn that the first option is usually right**. It trains on 246,678 rows with a loss that already includes KL to the frozen torso, rebuilds end to end in about 11 hours on one RTX 3090, and self-reports 0.779 accuracy, Brier 0.280 and ECE 0.072 on JevBench's 231 public tasks ([Strands Decider README](https://github.com/strands-labs/strands-decider), [architecture.md](https://github.com/strands-labs/strands-decider/blob/main/docs/architecture.md)). PostHog's Jeeves (Qwen3.5-9B with a pointer head, MIT) is the only decision model with a released RL trainer, CISPO, but that RL acts on reasoning chains before the decision, the pipeline expects eight GPUs, and CISPO did not improve v2 ([Jeeves](https://github.com/PostHog/jeeves)). Laya (ModernBERT-large, 421M, 34,808 stars) fine-tunes on two free T4s, but its 512 to 1,024 token context makes options share a fixed token budget, so it scores 0.425 on Banking77 against Jev's 0.870, and its repository measured no gain from its own `rlcd_loss` ([Laya README](https://github.com/NandhaKishorM/laya), [Laya train.py](https://github.com/NandhaKishorM/laya/blob/main/laya/train.py)). NanoJev (Qwen3-0.6B with game heads) leaves RLCD-style post-training on its roadmap ([NanoJev](https://github.com/TianyuCodings/NanoJev)). AgentJev-0.6B (Qwen3-0.6B, permutation-equivariant head, 2,048-token context) ships a Claude Code PreToolUse hook and the only released fine-tune on real coding-agent outputs, which cut failing test runs reported as green from 123 of 348 to none (self-reported) ([AgentJev](https://github.com/malevrigns/agent-jev)).

Activity is high but concentrated. ## Harnesses use Jev to pick, route and gate, but none lets it run the shell

### Six integration patterns report no measured savings

Six kinds of integration appeared between mid-September and late October 2026, and **none publishes tokens, cost, latency or task success with and without Jev**. Composio's provider returns a call, a partial call listing missing arguments, or an abstention, fills only enums, booleans and enum arrays, and reports the confidence of the least certain judgement ([Composio docs](https://docs.composio.dev/docs/providers/typesafe)). Microsoft's `agent-framework-typesafe` (MIT, alpha 1.0.0a261030 of 30 October 2026) makes Jev the whole tool-calling policy. Jev picks a tool, sees the result and picks another or none, with no LLM in the loop, at most 32 routable tools, and tools with free-form required arguments excluded ([PyPI](https://pypi.org/project/agent-framework-typesafe/)). AgentScope Java's middleware scores tools in OFF, SHADOW or ENFORCE mode and states that semantic decisions neither grant permissions nor prove that execution succeeded ([AgentScope Java](https://java.agentscope.io/v2/en/jev.md)). LangChain's `ModelRouterMiddleware` picks a model per run, and its experimental `AutoModeMiddleware` refuses risky bash calls without asking for approval ([LangChain blog](https://www.langchain.com/blog/building-a-harness-with-jev), [LangChain docs](https://docs.langchain.com/oss/python/integrations/providers/typesafe.md)). Among community MCP servers, jev-mcp's `jev_coding_loop` returns continue, retry, ask_user or stop plus a model tier, never touches git, files or the shell, and states that no cost reduction has been measured ([Glama, jev-mcp](https://glama.ai/mcp/servers/ic2fxc1p3e)). jev-router picks a Claude Code or Codex model tier once per user turn ([jev-router wiki](https://github.com/gargpratyush/jev-router/wiki)). Shell gates that call hosted Jev are common, jev-auto-approve and blastgate among them, but they gate an LLM's proposed command instead of choosing one ([jev-auto-approve](https://github.com/BasmaAbouzied0/jev-auto-approve), [awesome-decision-models](https://github.com/AnotiaWang/awesome-decision-models)).

The integrations fill three roles: Jev as the action policy over an enum-shaped tool set (Microsoft, Composio), Jev as a router or pre-filter for an LLM (AgentScope, LangChain, jev-router), and Jev as a gate or supervisor (`AutoModeMiddleware`, jev-mcp). **No project lets Jev or an open look-alike run `ls`, `cd`, `grep` or `cat` directly and hand generative steps to an LLM.** Microsoft's connector shows the policy half working mechanically and jev-mcp the escalation half, but nothing joins them. Trajectory caches save LLM calls by replay rather than by scoring a menu, and Agentic Plan Caching cuts cost by 50.31% and latency by 27.28% on average (self-reported) ([arXiv 2506.14852](https://arxiv.org/abs/2506.14852)).

### SwiftSage, When2Ask and Ctrl-Z bracket the course design

Three academic works bracket the design. SwiftSage (Lin et al., NeurIPS 2023) is closest in structure. A small fine-tuned module acts and an LLM planner is called for hard steps, and it beat SayCan, ReAct and Reflexion on 30 ScienceWorld tasks, but its fast module is generative and imitation-trained ([arXiv 2305.17390](https://arxiv.org/abs/2305.17390)). When2Ask (Hu et al., RLC 2024) is closest in method. It casts the timing of LLM queries as an MDP and learns with RL when the agent should ask, needing only a few LLM interactions on MiniGrid and Habitat, but it has no shell, abort or danger actions ([arXiv 2306.03604](https://arxiv.org/abs/2306.03604)). Ctrl-Z (Bhatt et al.) is closest on safety. A trusted monitor scores each step of a multi-step bash agent on BashBench, and resampling protocols cut attack success from 58% to 7% at a 5% cost to benign performance, though the monitor never chooses actions ([arXiv 2504.10374](https://arxiv.org/abs/2504.10374)). ReDAct sets the cost bar for threshold deferral by matching the large model on ALFWorld and MiniGrid with about 15% of decisions deferred ([arXiv 2604.07036](https://arxiv.org/abs/2604.07036)), and in RelayLLM a small model trained with GRPO calls a large one for 1.07% of tokens ([arXiv 2601.05167](https://arxiv.org/abs/2601.05167)). Barbosa proposes non-generative classifiers with calibrated verdicts at four decision points of a pentest harness, warns that Jev's benchmark results need not transfer, and defines no training objective ([arXiv 2609.28940](https://arxiv.org/abs/2609.28940)). Cascades and routers such as FrugalGPT route per query ([arXiv 2305.05176](https://arxiv.org/abs/2305.05176)), while the course design routes per step inside an episode, which makes RL credit assignment, not supervised routing, the natural formulation.

The best-measured deployed overseer is an LLM classifier, not a decision model. For Claude Code's auto mode, Anthropic reports a 17% false-negative rate on 52 real overeager actions and a 0.4% false-positive rate on 10,000 real tool calls (self-reported) ([Anthropic engineering](https://www.anthropic.com/engineering/claude-code-auto-mode)). The independent AmPermBench stress test measured an **81.0% end-to-end false-negative rate** over 253 state-changing actions ([arXiv 2604.04978](https://arxiv.org/abs/2604.04978)). The two figures come from different distributions, so a dangerous-action rate means little without a fixed, public danger set. The gap the project addresses is Open. No prior work puts a non-generative typed model in charge of a shell agent whose single action space holds a mined menu of frequent commands plus abort, flag-danger and defer-to-LLM. None trains such a model with RL against a reward that charges for LLM calls and danger, or reports success, LLM calls and dangerous-action rate on a public benchmark.

## Calibration-aware RL helps where actions change outcomes and fails when misbuilt

### Open objectives agree that supervised training plus a temperature is the bar

Five open efforts implement a proper-scoring objective inside RL, and none reproduces TypeSafe's, which is unknown.

| Project | Objective | Model | Main self-reported finding |
|---|---|---|---|
| decider v10 | PPO on outcomes, log-score belief against the exact law, KL anchors | Qwen3.5-2B | browser success 83.0% to 93.2%, belief excess 0.473 to 0.219 nats |
| rlcd-lite | GRPO, which reduces to REINFORCE with a group baseline, under binary, Brier or RLCR rewards | Qwen2.5-0.5B with LoRA | a Brier-only reward drove accuracy to 0.21 at stated ECE 0.086, RLCR reached 0.78 at 0.084 |
| mini-jev | SFT, distillation from Jev, GRPO with a proper-score reward | Qwen3-1.7B with QLoRA | per-group std normalization inflated confidence (ECE 0.342), a mean-only baseline fixed it (0.084) |
| open-rlcd | importance-weighted proper score on stated option probabilities | toy model and a 9B | no clear gain over supervised training plus temperature, except Breakout belief log loss 0.488 against 0.592 (one seed) |
| OpenJev-RLCD | calibrate with a proper score, then reinforce rationales with leave-one-out REINFORCE and a KL anchor | Qwen3-1.7B, three seeds | coverage at 5% error 81.1% against 19.4% for GRPO with KL on GSM8K-Verify |

Sources for the table are [decider RL.md](https://github.com/Mapika/decider/blob/main/docs/RL.md), [rlcd-lite](https://github.com/arnabgho/rlcd-lite), [mini-jev](https://github.com/Shauryagulati/mini-jev), [open-rlcd](https://github.com/Louiskq/open-rlcd) and [arXiv 2609.38850](https://arxiv.org/html/2609.38850v1). The findings converge on four failure modes. A Brier reward on stated confidence alone is a trap, because the policy learns to be predictably wrong at low confidence, which rlcd-lite saw as accuracy collapsing to 0.21 while stated ECE looked good. Every RL arm in rlcd-lite pushed the raw softmax to a mean confidence of 0.99 to 1.00, and one fitted temperature repaired much of it, consistent with decider's stored temperature of 1.30 and Jeeves' separate post-reasoning temperature ([Jeeves](https://github.com/PostHog/jeeves)). GRPO's per-group standard-deviation normalization inflated confidence in mini-jev, and merging the QLoRA adapter into the 16-bit base raised ECE from 0.005 to 0.080. OpenJev-RLCD adds a structural result, that the score of a mixture of rationales equals the average per-rationale score plus a disagreement bonus that rewards randomness. It also reports that end-to-end training collapses to empty rationales or drowns in policy-gradient noise unless calibration comes first. open-rlcd's conclusion carries furthest, since it finds that RL fixes RLVR's overconfidence but beats supervised training plus temperature only where outcomes depend on the model's own moves, which is the agent-harness case. Each of these is a single-scale, few-seed, unreviewed result.

### Academic work moved from RLHF's calibration loss to bounded proper-score rewards

RLHF damages token-level calibration, which is the readout a Jev-style model uses. The GPT-4 report plots MMLU answer-option calibration with ECE 0.007 before and 0.074 after PPO post-training (Empirical) ([arXiv 2303.08774](https://arxiv.org/abs/2303.08774v2)). Kadavath et al. find RLHF policies miscalibrated at temperature 1 but fairly well calibrated after a simple temperature change (Empirical, 52B models) ([arXiv 2207.05221](https://arxiv.org/abs/2207.05221)). Bereket and Leskovec show that GRPO yields overconfident probabilities for stochastic outcomes while PPO and RLOO stay calibrated, and that removing GRPO's group standard-deviation normalization fixes it (Empirical, with supporting theory) ([arXiv 2508.11800](https://arxiv.org/abs/2508.11800)). Kapoor et al. show that LoRA fine-tuning on about a thousand graded examples beats prompting baselines for uncertainty estimation (Empirical) ([arXiv 2406.08391](https://arxiv.org/abs/2406.08391)).

RLCR (Damani et al., ICLR 2026) is the closest published analogue of what commentators guess RLCD to be. The model answers and states a confidence, and the reward is a correctness indicator minus the squared gap between confidence and correctness ([arXiv 2507.16806](https://arxiv.org/abs/2507.16806)). The paper proves that any bounded proper scoring rule can replace the Brier term as long as its gap between correct and incorrect scores stays below the correctness bonus, which makes the optimum both accurate and calibrated. The log score fails that condition because its gap is unbounded near zero confidence (Proven) ([arXiv 2507.16806v2](https://arxiv.org/html/2507.16806v2)). On HotpotQA, RLCR cut ECE from 0.37 to 0.03 against RLVR at about equal accuracy (Empirical). The Li et al. survey derives the same reward by averaging the answer and abstain utilities of Wu et al.'s behaviorally calibrated RL over a uniform threshold (Proven, for that utility scaling) ([Li et al. survey](https://yubol-bobo.github.io/rlcd-survey/pdf/calibration-aware-rl-survey.pdf), [arXiv 2512.19920](https://arxiv.org/abs/2512.19920)). Kalai et al. show that stating a target t, penalizing wrong answers by t/(1−t) and scoring abstention at zero makes answering optimal exactly when confidence exceeds t, for every t (Proven) ([arXiv 2509.04664](https://arxiv.org/html/2509.04664v1)). TruthRL's ternary reward cut hallucination from 43.5% to 19.4% but gave up some correct answers and measured no probability calibration (Empirical) ([arXiv 2509.25760](https://arxiv.org/abs/2509.25760)). The survey also summarizes Che et al., who show that abstention as a learned action can kill both the reward gradient and the KL anchor when training success is low, a paper not read directly. In agentic RL, RefGRPO's reflection bonus cut underconfidence from 44.4% to 7.7% on text-to-SQL ([arXiv 2606.14211](https://arxiv.org/abs/2606.14211)), and Xuan et al. find that evidence tools such as web search induce overconfidence while verification tools such as code interpreters reduce it ([arXiv 2601.07264](https://arxiv.org/abs/2601.07264)), both Empirical.

### Proper scores certify a fixed event, and an agent loop has none

A strictly proper scoring rule is optimized in expectation only by reporting the true distribution (Proven, Gneiting and Raftery 2007) ([DTIC report](https://apps.dtic.mil/sti/html/tr/ADA459827/index.html)). Given a calibrated correctness probability, the cost-optimal defer rule is a fixed threshold set by the ratio of an error's cost to the total, so moving the threshold retunes the system without retraining (Proven, elementary) ([Li et al. survey](https://yubol-bobo.github.io/rlcd-survey/pdf/calibration-aware-rl-survey.pdf)). Learning to defer has consistent surrogate losses (Mozannar and Sontag, Proven) ([arXiv 2006.01862](https://arxiv.org/abs/2006.01862)), selective classification has the risk-coverage curve ([arXiv 1705.08500](https://arxiv.org/abs/1705.08500)), and LLM cascades gain from a learned deferral rule on token-level uncertainty ([arXiv 2404.10136](https://arxiv.org/html/2404.10136v1)). An agent loop breaks these premises. The chosen command changes the next state, so the label of the correct action depends on the policy, and a per-step proper score no longer certifies calibration of episode outcomes. Deferring now also trades against deferring later, which SLTD handles with value-based deferral ([arXiv 2109.06312](https://arxiv.org/abs/2109.06312)) and KnowNo with conformal coverage over a planner's options ([arXiv 2307.01928](https://arxiv.org/abs/2307.01928)). Per-step calibration does not compose either, since ten steps accepted at 0.95 succeed together with about 0.6 probability only if their errors are independent, and agent errors are correlated (Heuristic). **No paper combines RL-trained calibrated action probabilities with deferral to a larger LLM inside a multi-step agent** (Open).

The metrics follow from these results. Brier and NLL are the headline because they are proper, ECE with a reliability diagram and bootstrap intervals is the diagnostic, AUROC measures separation of correct from incorrect decisions, and AURC with coverage at fixed error measures the deferral trade-off ([Guo et al., ICML 2017](https://proceedings.mlr.press/v70/guo17a.html), [arXiv 1705.08500](https://arxiv.org/abs/1705.08500)). rlcd-lite warns that ECE is biased upward on small samples and that calibration without resolution is uninformative, with its RLCR arm at AURC 0.21 against 0.07 for temperature-scaled softmax ([rlcd-lite](https://github.com/arnabgho/rlcd-lite)). Before computing ECE, the event behind each probability has to be fixed, whether the chosen action is right or each option is right, because TypeSafe's `confidence` is a summary of distribution shape.

## What the evidence implies for the COMP538 controller

### Train decider-2b and debug the objective on Kev-0.8B

Jev itself can only be a baseline. Its weights are closed and shared, so RL can tune the wrapper around it (option set, descriptions, state encoding, thresholds) but never the model ([TypeSafe docs, Models](https://docs.typesafe.ai/models)). The base to train is **Mapika/decider-2b**, starting from the Hub tag `v10`, the documented RL checkpoint, unless the team confirms that the current v12 inherits that stage. The v10 recipe already has the project's shape, a one-pass Choice over environment actions trained with PPO on the served softmax, plus a belief term and retention gates. The released SFT pipeline, temperature fitting and Brier, ECE and AURC evaluation remove most of the scaffolding ([decider RL.md](https://github.com/Mapika/decider/blob/main/docs/RL.md), [decider README](https://github.com/Mapika/decider)). Inference needs about 4 GB, so rollouts fit beside training on one GPU, and the 32k context and 255-option ceiling cover shell histories and long menus.

Three costs come with decider. The team has to rewrite the RL loop from RL.md, because the code is unreleased. The letter-slot readout ties options to label tokens, so option order matters, and decider's two-order averaging and consistency KL should be kept. The 2B model ignores rules written into the question, so harness conventions such as what abort means and when to flag danger have to be taught through training data rather than prompts ([decider README](https://github.com/Mapika/decider)). The team should also expect to start far below Jev, given decider-2b's 28.97 against Jev's 57.91 on the Decision Index, so the claim to test is the RL gain over the base, not parity with Jev.

Kev-0.8B is the sandbox for debugging the objective, at about 20 minutes per training stage on one H100, with a documented `--init_from` path and Brier, calibration-error and option-order metrics in its benchmark ([Kev README](https://github.com/jaredpalmer/kev)). Its pointer head, like Strands Decider's, has no per-option parameters, so commands can be added or removed while the menu length is tuned. Strands Decider 2B shares the pointer head and is the fallback base if decider's order sensitivity dominates the ablations ([Strands Decider README](https://github.com/strands-labs/strands-decider)). rlcd-lite's 0.5B LoRA setup, at about 7 minutes per arm on a laptop, is the fastest place to test a reward before scaling ([rlcd-lite](https://github.com/arnabgho/rlcd-lite)). Qwen3.5 bases mix attention with Gated DeltaNet layers that ignore attention masks, so each question runs as its own row and `flash-linear-attention` is needed on CUDA ([Kev README](https://github.com/jaredpalmer/kev)).

### Reward outcomes, add a bounded Brier belief term, and split off danger

The objective the evidence supports has two stages. Stage one fits the softmax over menu commands, abort and fallback with log loss against labels on recorded harness states. The label is the gold command where it appears on the menu and fallback where the gold step needs an argument the menu lacks, and one temperature is then fitted on held-out states. Stage one is the floor RL must beat, since across open-rlcd, rlcd-lite and decider supervised proper-score training plus a temperature is hard to beat whenever labels exist. Stage two rolls out the agent on the served softmax and optimizes an episode return made of task success minus a cost per LLM call, a penalty for any dangerous command that executes, and a cost for abort on a solvable task. The actor term should use PPO or RLOO with a leave-one-out baseline over replicate rollouts of the same task and **no per-group standard-deviation normalization** ([arXiv 2508.11800](https://arxiv.org/abs/2508.11800), [mini-jev](https://github.com/Shauryagulati/mini-jev)).

Calibration enters through a belief question at each step, a Noul predicting whether the chosen command will succeed or change the state, scored by Brier against what happened. decider could use a log score because its games have exact laws, but a shell has none, and wherever the event depends on the model's own action RLCR's boundedness result and rlcd-lite's trap both argue for Brier ([arXiv 2507.16806v2](https://arxiv.org/html/2507.16806v2), [rlcd-lite](https://github.com/arnabgho/rlcd-lite)). A retention KL to the stage-one model with drift gates and a consistency KL across option orders complete the loss, as in decider. A temperature refit follows, and calibration is re-measured after any adapter merge ([decider RL.md](https://github.com/Mapika/decider/blob/main/docs/RL.md), [mini-jev](https://github.com/Shauryagulati/mini-jev)). The combined design is Heuristic, because each part has worked somewhere and the combination has never run in a shell harness.

Fallback, danger and abort each need their own treatment. The theory favors fallback as a threshold on the calibrated top-action probability, set from the LLM's cost relative to an error's cost, because one trained model then serves every LLM price. A learned abstain option risks the collapse Che et al. describe, and rlcd-lite's 0.5B model never learned its needs-human field ([Li et al. survey](https://yubol-bobo.github.io/rlcd-survey/pdf/calibration-aware-rl-survey.pdf), [rlcd-lite](https://github.com/arnabgho/rlcd-lite)). The project's design makes fallback a menu option, which is the When2Ask formulation and can learn timing that a fixed threshold cannot, so both arms should run, with the threshold rule as the baseline. Jev's step confidences of 0.71 when right and 0.72 when wrong show that a threshold works only if training creates separation between right and wrong steps, so **AUROC of step confidence is the deciding metric** for either arm. Danger is not exclusive of a command choice and its costs are asymmetric, so a separate Noul with a low, cost-weighted threshold fits better than one more softmax slot (Heuristic). Abort needs an explicit negative utility so that it does not become the safe default, which is Kalai's guessing argument run in reverse. A cheap extra arm puts a confidence target into the state and penalizes wrong actions by the target's odds, so one policy learns behavioral calibration for every threshold ([arXiv 2509.04664](https://arxiv.org/html/2509.04664v1)).

### Run six baselines on InterCode-Bash and BashArena

Six baselines bracket the result. An LLM-only agent gives the success ceiling and the cost ceiling. Hosted Jev zero-shot gives the vendor's best case, using the Bonn protocol of one Choice over the menu with full history and argmax plus a Vercel-style fallback below confidence 0.6. It should be pinned to `jev-1.13.0` for comparability with the published evaluations and rerun on `jev-1.14.0`, and at the Bonn study's rate of $9.40 for 346,009 requests it costs a few dollars ([arXiv 2609.37647](https://arxiv.org/html/2609.37647), [Vercel docs](https://vercel.com/docs/ai-gateway/sdks-and-apis/typesafe.md)). The zero-shot open base isolates the effect of training, SFT plus temperature is the floor, binary-reward RL shows the overconfidence the belief term should remove, and a TruthRL-style ternary reward with a fixed fallback cost is the direct-action alternative. LitJev's training-free readout and a ReDAct-style threshold deferral are cheap optional rows ([LitJev](https://github.com/zhengxuyu/litjev), [arXiv 2604.07036](https://arxiv.org/abs/2604.07036)). Every run should report episode success, LLM calls and tokens per episode, dangerous-action rate on a fixed public set, per-step NLL, Brier and ECE with bootstrap intervals, AUROC of step confidence, AURC, a success-against-cost curve over the fallback threshold, and option-order sensitivity. Because Jev's determinism is undocumented and the Bonn study ran each request once, a sample of baseline requests should be repeated to measure variance.

InterCode-Bash should carry success and LLM-call count, because its Gym interface fits the RL loop and its tasks come from NL2Bash, whose utility and flag statistics can seed the menu ([InterCode repo](https://github.com/princeton-nlp/intercode), [NL2Bash repo](https://github.com/TellinaTool/nl2bash)). The shared origin creates a leakage risk, because the available material does not say which NL2Bash items InterCode-Bash uses. The menu should therefore be mined from a split known to be disjoint from the evaluated tasks, or from the agent's own logs on training tasks. Before any training the team should measure menu coverage, the share of gold steps whose exact command string is on the menu, because coverage caps the share of steps the decision model can take and sets a floor on the fallback rate. Commands with task-specific arguments will mostly fall to the LLM, and a dynamic menu that enumerates arguments from the state, such as file names from the last `ls`, is the natural extension if coverage is low. Dangerous-action rate belongs on BashArena's side tasks or BashBench, with AmPermBench as a destructive-action check, and Terminal-Bench 2.0 serves only as a held-out stress subset ([arXiv 2512.15688](https://arxiv.org/abs/2512.15688), [arXiv 2504.10374](https://arxiv.org/abs/2504.10374), [arXiv 2604.04978](https://arxiv.org/abs/2604.04978), [arXiv 2601.11868](https://arxiv.org/abs/2601.11868)).

### Sequential weakness and injected text are the main risks

The sequential weakness comes first. Jev, the most refined model of its type, completes fewer ALFWorld and TextWorld tasks than an open autoregressive LLM, repeats actions with no effect, re-enters dead ends in its own history, and gives right and wrong steps the same confidence ([arXiv 2609.37647 HTML](https://arxiv.org/html/2609.37647)). A 2B look-alike starts lower. The harness should mask repeated no-effect commands and ask a companion Noul on whether the last command changed anything. Outcome descriptions in option text are worth testing, since they doubled FrozenLake accuracy, but they hand part of the reasoning to the prompt. How to assign per-step credit for terminal success without damaging per-step calibration has no tested answer (Open).

Prompt injection comes second. Every command output, from file contents to README text, is untrusted state, and a file that redefines "dangerous" could push the danger probability under threshold, as Datadog's counterfeit policy pushed `is_risky` from 0.893 to 0.290 ([Datadog Security Labs](https://securitylabs.datadoghq.com/articles/jev-as-a-judge-how-counterfeit-policy-steers-jev/)). HiddenLayer's converted Qwen behaved like Jev under attack, so an open base inherits the weakness ([HiddenLayer](https://www.hiddenlayer.com/research/system-one-model-security)). The danger flag and abort can recommend but must not authorize, so a deterministic deny-list and a sandbox sit beneath them, as AgentScope's own documentation insists ([AgentScope Java](https://java.agentscope.io/v2/en/jev.md)). The evaluation should include files that carry counterfeit policies.

The remaining risks are mechanical. First-option bias is documented for Jev, about 7% of JEV-27B's answers change with option order, and reshuffling flipped about half of base decisions in rlcd-lite, so option order must be randomized or fixed and reported, with an ordering ablation ([TypeSafe docs, Jev 1.13 jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md), [JEV-27B card](https://huggingface.co/autotrust/JEV-27B), [rlcd-lite](https://github.com/arnabgho/rlcd-lite)). RL drifts at learning rates that look safe, as decider's failed 2e-6 run shows ([decider RL.md](https://github.com/Mapika/decider/blob/main/docs/RL.md)). Long episodes approach Jev's 32k per-question limit, and its long-context mode is less accurate by TypeSafe's own account, so the state should be truncated in code ([TypeSafe docs, Models](https://docs.typesafe.ai/models)). Jev's aliases move, so thresholds must be tuned against a pinned version. TypeSafe's terms on training with Jev outputs were not checked, which matters only if Jev's distributions become training labels, as they did for JEV-27B and mini-jev.

## Conclusion

The landscape inverts the question the project started from. Jev clones are abundant, about fifty in one list, but evidence that a one-pass decision model can run a multi-step loop is scarce, and the only independent test says the best such model cannot yet, with confidence that carries no step-level signal. The project's contribution therefore lies in sequential control, and its headline metrics should be AUROC of step confidence and success per LLM call rather than single-question ECE, on which Jev and an open LLM already tie. A negative result would still locate the failure, in the decision model or in the coverage of the command menu, which is why coverage should be measured before anything is trained.

RLCD's opacity helps a course project, because a framing without a method leaves the team free to own the objective and state it exactly. The defensible version is assembled from parts that each worked somewhere (an outcome return with explicit costs, a bounded Brier belief term, a leave-one-out baseline, a KL anchor, a temperature refit) and have never been combined in a shell harness. The security results change the architecture more than the objective. Because text in the state can redefine the criteria, the danger flag can only save cost on the obvious cases, and the deterministic sandbox beneath it belongs in the design from the first experiment.
